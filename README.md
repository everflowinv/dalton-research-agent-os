## 1. Dalton 是什么，为什么要做它

### 1.1 一句话定义

Dalton 的角色定位是一名**常驻系统、严守纪律的初级分析师（Junior Analyst）**。它严格遵循基金内部的专业投研手册展开工作，持续从法定定期财报、业绩电话会纪要、券商研报以及权威公开资讯中搜集素材，逐字深度研读，将具有投资价值的事实提炼为一条条附带精确出处的“结构化事实（Claims）”；进而以此为坚实底稿，自主起草初步筛查报告（Initial Screen）、公司全景深度档案（Dossier）、多空博弈争议地图（DebateMap）、动因驱动型财务模型（Financial Model）以及投资备忘录（IC Memo）。它不是陪聊的聊天机器人，不会消极等待分析师提问才行动，但也绝不擅自越权替投资人做最终买卖决策。

### 1.2 它要解决的根本问题

通用大语言模型（如常规对话式 AI）在严肃的二级市场基本面投资中始终难以真正落地，核心症结并非大模型不够聪明，而是欠缺以下四项关键特质：

- **缺乏长期记忆。** 每次开启新对话均从零开始，无法像资深分析师一样，在数月乃至数年的跨度中持续积累对标的公司业务变迁、管理层风格与财务披露习惯的连续认知。
- **缺乏主动研究议程。** 它只能被动等待人类喂入资料或发起提问，无法主动识别当前哪家标的的资料底座存在缺失、哪条核心投资论点最脆弱、以及下一步应该优先补全哪些关键前瞻数据。
- **财务数据不可信。** 生成的行文看似头头是道，引用的财务与营运数据却经常张冠李戴甚至凭空捏造。在二级市场投资中，一个错误的财务指标就足以彻底推翻整份报告的逻辑基石。
- **迎合市场平庸共识。** 输出往往充斥着全市场早已熟知的泛泛之谈。而与大众共识完全一致的观点，无法为买方投资带来任何超额收益（Alpha）。

Dalton 的解法是彻底将这些问题从“如何写好提示词（Prompt）”升级为“如何搭建确定性的系统架构”：

- **把投研方法论沉淀为刚性契约。** 将基金内部成熟的分析师培训手册，转译为计算机可自动校验的六阶段流程，每个阶段均明确设定了必读材料清单、必交交付物规范与客观出口质量关卡。
- **把所有底层事实记入不可篡改的账本。** 每一句提炼出的核心结论，都必须逐字锚定原始文档的精确字节位置；每一个具有时效性的数据，都必须精准回溯至 SEC 官方申报文件或当期工具采集结果，否则整节内容将被安全机制直接丢弃。
- **把投研认知沉淀为可演进的数据对象。** 公司全景档案、多空争议地图、财务预测线均为带版本追踪、可动态演化的结构化记录，彻底摆脱了随聊随丢的即时聊天上下文依赖。
- **让人类专注高阶判断，彻底告别底层体力活。** 分析师无需再逐份审核原始文档或逐句批准事实条目，只需在关键的投资认知与评审关卡前做最终裁决。

### 1.3 它不是什么

- **它不是自动化股票交易系统。** 它只负责梳理基本面事实、构建财务预测并提出研究假说，最终的投资组合仓位与交易决策必须由人类投资人全权负责。
- **它不是宽泛问答的聊天机器人。** 其即时问答功能仅严格基于已核实入库的事实底座作答；面对未收录的信息，它会直接说明信息缺口，绝不胡乱猜测。
- **它不是泛用型的通用 AI 平台。** 它只聚焦于一个核心业务目标：按照投研手册的规范，将特定行业和一组标的公司从首次覆盖扎实推进至日常持续跟踪。

## 2. 人机分工：人做什么，机器做什么

这一权责边界自项目确立之初便作为底层铁律严格执行。

```
┌──────────────────────────────────────────────────────────────┐
│  人类（基金经理 / 分析师）只做四件事                              │
│                                                              │
│  1. 确立研究目标与边界  指定研究行业、首批覆盖标的、每日算力预算上限  │
│  2. 提供策略指引与纠偏  “本周重点深挖 IBM 软件业务”、“忽略公关通稿” │
│  3. 把关关键评审关卡    深度认知门、投资备忘录、论点准入、扩范围扩预算│
│  4. 审阅资产、做出决策  阅读公司深度档案与财务模型，决定交易与仓位    │
└─────────────────────────────┬────────────────────────────────┘
                              │ 目标 · 指引 · 裁决
                              ▼ 产物 · 事实 · 待办
┌──────────────────────────────────────────────────────────────┐
│  Dalton 自主完成其余一切重活与细活                              │
│                                                              │
│  · 对照投研手册的资料底座缺口，自主规划材料搜集与抓取顺序          │
│  · 逐段研读原始文献，提炼附带字节级精准引文的事实结论              │
│  · 自主起草初筛报告、公司深度档案、争议地图、行业框架、模型规格      │
│  · 调用跨厂商的独立模型，对每一份起草成果实施对抗性交叉复核        │
│  · 对照出口门标准自检自评，未达标时列明缺口并自主回溯补齐资料      │
│  · 日常不间断追踪市场动态事件，输出影响研判；每周撰写简报与复盘    │
│  · 严格受制于单日资金预算与接口配额，一旦超限即刻优雅停机待命      │
└──────────────────────────────────────────────────────────────┘
```

**必须由人类决策的事项是一张封闭且明确的白名单**，写入在任务契约中，系统仅允许追加、严禁私自删减：

| 关键检查点 | 业务内涵与决策意义 |
| :--- | :--- |
| **研究论点准入** | 一项全新的核心投资逻辑（Thesis）首次进入正式投研账本，必须由人类分析师签字签发。 |
| **投资论点修订** | 系统可主动提出“现有证据表明某项核心逻辑可能被削弱”，但唯有人类能够批准采纳该修订提案。 |
| **深度认知门** | 系统负责起草 12 项关键投研问卷的详尽答卷，是否准予通过该阶段评审全由人类定夺。 |
| **投资备忘录** | 系统完成全篇起草并由独立模型复核后，必须经人类签署方可确立为投委会正式观点。 |
| **关卡重开评估** | 对于已通过初筛的标的，在底层财务数据大幅扩充更新后，是否推倒重出一版报告由人类裁决。 |
| **预测偏差处置** | 当公司披露的实际财报数据与此前模型的预测偏差超出容忍阈值时，后续处置动作须经人类确认。 |
| **高置信判断采纳** | 系统基于预期差挖掘出的“高置信下注建议（Conviction Call）”，由人类负责最终采纳、驳回或搁置。 |
| **扩范围、扩预算、扩权限** | 涉及扩大覆盖股票名单、上调算力费用上限或放宽系统写入权限时，必须由人类显式发布新版任务合同。 |
| **启用新工具或新数据源** | 接入任何新的外部商业数据库或底层系统功能变更，均须经过专门的人工治理审批。 |

除此之外的所有日常执行环节（包括海量单份文档的研读、单条事实结论的校验入库），均交由系统自主闭环处理，不再需要人类逐条点击确认。

## 3. 六条核心设计原则

这些原则决定了系统如今的架构形态，每一条在底层的架构决策记录（ADR）中均有据可循。

1. **无聊的确定性内核，聪明的大模型边缘（Boring Kernel, Smart Edges）。** 调度排程、事实账本、费用预算、会计勾稽校验等核心逻辑，全部采用严密的确定性代码逻辑锁死，坚决不交给大模型自由发挥。大语言模型只作为“按需调用的计算单元”部署在三处认知刀刃上：从长文中提炼高密度事实、将事实组织为结构化研究篇章、以及充当独立复核者对抗性审查草稿。大模型是系统雇佣的算力，而不是操纵系统的中枢大脑。
2. **所有出处必须可重算验证，绝不接受任何组件自报事实。** 系统坚决不采信任何组件自己声称的事实。大模型不能自称使用了哪家底层服务，任务执行器不能自称“已经跑完”，外部调用方不能自称“已获得权限”。全系统采用底层内容哈希逐层锚定校验，任何一个参数或依赖与登记不符，底层机制立即拒绝放行。这确保了报告中出现的每一个财务数字，都能沿着时间链条一路倒查验证到原始抓取文件的物理字节。
3. **正文每个时效数字必须精准回指原文出处。** 报告正文中的每一个具备时效性的定量指标，都必须在底层绑定一条定量事实的逐字引文，否则必须直接标注为“【数据源缺失】”。任何未经合规换算凭空推导的数字都会被拦截，若某一章节包含无法查证出处的数字，该章节将被直接整体丢弃。系统绝不允许大模型自由发挥捏造数据。
4. **历史版本永久留痕，严禁任何机制暗中篡改历史。** “已通过评审”、“已正式发布”、“已人工接受”都只是针对“某一特定历史版本”的状态标记，而非该研究资产的永久终态。只要底层证据补充扩充了、公司披露了新的实际财报、测算假设经过了重新核实、或者人类修改了观点，系统都会生成一份附带充分理由的新版本；历史版本永久留痕、只追加不覆盖。然而，数据库底层只提供“登记改版”的入口，绝不存在自我悄然篡改的机制。是否需要生成新版本，必须由专门的研判层驱动。甚至一条长期只有单一版本的演进链本身也是极其宝贵的信息——它明确表明分析师团队对该核心逻辑的判断从未发生动摇。
5. **全系统确立唯一定量与定性事件入口。** 任何试图向系统表达“外部市场发生新动态、投研逻辑应当做出反应”的信息流，都必须统一登记为规范的“研究事件（ResearchEvent）”，走同一条研判处理车道、消耗同一个预算配额池、并输出标准化的五项决策词汇之一。系统彻底废弃并退役了早期冗余的多套事件分支，确保全系统对市场冲击的感知标准完全统一。
6. **预算约束先于自主行动。** 任何自主研究流水线得以发起模型调用并产生实际费用的前提，是人类在任务授权与系统治理策略中，白纸黑字签署了封闭明确的预算硬顶；缺失显式配置绝不等于默认无限制授权。每日预算被严密隔离切分为不同的专项资金池，某条流水线一旦超额，当天立即自动跳过并直接在驾驶舱界面亮明状态。

此外，还有一条贯穿所有研究交付物起草的硬性约束：**与市场共识完全一致等于没有观点。** 在多空争议地图、即时问答以及高置信判断等各个模块中，系统均内置了硬性校验规则：如果系统推演出的观点与华尔街卖方共识毫无二致，系统将视其为“零增量价值”。Dalton 核心要回答的投研问题是：资本市场当前的共识定价究竟错在哪里？后续有什么明确的因果路径能推动市场共识向我方的判断收敛？

### 六个层级各自的业务职责：

1. **数据源接入层**：只负责连接特定数据供应商并执行具体的抓取动作，返回可供审计的原始报文与文件。该层级不做任何主观投研判断，拿到的所有文献首先落盘为带数字指纹的原始文件，经合规核验后方可送入下一层。
2. **统一研究事实底座（Research Ledger）**：整个系统的长效记忆与事实权威中心。瞬时聊天记录、临时会话摘要绝不被视为研究事实，唯有登记在账本中不可篡改的证据、事实结论以及论点版本链方为有效资产。
3. **任务授权与研究手册层**：回答“系统当前该做什么”。任务契约规定了覆盖哪些标的、允许调用哪些数据源、机器能够写入哪些对象、哪些事项必须等待人类裁决；研究手册则明确了每个阶段必须研读什么、必须提交什么、达到何种标准才允许过门。
4. **认知演进与财务模型层**：负责将零散的事实原子凝练为条理清晰的投研交付物，把 SEC 申报表行转化为具备前后勾稽关系的财务预测模型。每份交付物均必须通过另一家技术厂商大模型的对抗性独立复核。
5. **模型路由与预算风控层**：决策每一次算法调用分配哪一家大模型、允许支出多少费用。任何一次模型切换均会在底层留存不可更改的路由决策记录，严禁供应商私自静默降级。
6. **投研专属控制台（Cockpit）**：分析师日常交互的唯一视窗。该界面彻底隐去了枯燥的任务队列、数据哈希或内部调试代码，专注于呈现研究目标、策略指引、执行动态、穿透问答以及待办审批事项。

### 运行形态与部署架构

Dalton 部署在一台专用的 Mac 硬件设备上，由四个常驻后台守护进程协同驱动：

| 守护进程 | 业务作用与职责 |
| :--- | :--- |
| **writer** | 事实账本的唯一写入中枢。所有业务子模块的持久化请求均必须经过它排队写入，杜绝多线程写冲突与数据污染。 |
| **controller** | 系统的巡检调度心跳。每隔几秒钟进行一次状态轮询（tick），按顺序检查各项研究流水线：是否到了搜集新资料的时间、是否有新文档排队等待阅读、初筛报告是否满足起草条件、周报是否到了生成节点。在系统空闲期，它仅负责维护健康心跳、刷新驾驶舱只读投影与回收超时租约。 |
| **control（控制台）** | 投研人机交互的前端控制台。服务仅绑定在本地回环网络，通过安全的 Tailscale 虚拟局域网向分析师授权设备提供加密的 HTTPS 访问，确保私有投研数据绝不暴露于公网。 |
| **thesis-impact** | 独立的周期性轻量研判任务，负责监控新入库事件是否对现存投资论点产生冲击。 |

大模型工作计算进程并不常驻占用资源。每一次文档研读或报告起草，都是一个具备严格超时控制、资金预算限制与防重放机制的瞬时子任务，执行完毕即刻退出释放资源。

所有业务数据（数据库、模型配置、治理审批记录、历史快照、审计日志）均严格存放在主机用户目录下的专属受保护文件夹中，绝不随源代码公开。

### OpenClaw 在架构中的角色定位

OpenClaw 是宿主环境中已部署的基础 AI 代理网关，集中管理着各家大模型厂商的 API 鉴权账号以及部分外部工具能力（如基础网络搜索、专家网络检索、内部知识库向量索引）。Dalton 仅通过受限的本地中间件借用其已配好的认证通道发起请求，自身绝不触碰或读取其敏感密钥文件。

反之，OpenClaw 也绝非 Dalton 的运行时核心、数据库或事实来源。模型吐出的任何文本，必须回到 Dalton 严密的确定性校验与签名流程中接受检验。通俗而言：**OpenClaw 充当的是系统的“眼和手”，而 Dalton 牢牢掌控着真正的“大脑记忆、投研逻辑与最终签字权”。** 外部世界看到的信息绝不会自动转化为系统记忆，其间必须经过严密的重新计算与合规确认。

## 5. 核心概念词典

| 核心术语 | 专业白话解释 |
| :--- | :--- |
| **Evidence（原始证据）** | 对一份外部原始文献的正式登记记录：包含数据源出处、获取时间、有效期限、完整数字指纹以及独立性分组标记。 |
| **Claim（结构化事实）** | 从原始文献中深度提炼出的单句结构化事实陈述。包含定性事实（如“管理层表示生成式 AI 业务目前尚未展现出与传统外包显著不同的毛利率特征”）与定量事实（如特定季度的营业收入）。每条事实均逐字锚定在原始文献的精确字节位置上。其真实性状态不可人为随意硬编码，只能由证据链条及逻辑推演得出。 |
| **Thesis（核心投资论点）** | 一项严肃的投资价值判断，底层绑定一组事实依据、前瞻催化剂与反向证伪条件。置信度仅分为低、中、高三档（不搞虚假的伪精确概率）。一项核心论点在首次确立时，必须由人类分析师签字生效。 |
| **Claim 挑战与退役** | 机制性纠错手段：当系统发现某条既有结论存在归属错误（如引文内容实际并非描述该标的）或源自无意义的免责声明时，系统会追加一条挑战记录将其标记退役。退役事实即刻从问答库与交付物上下文中剔除，但历史留痕可查。 |
| **CoverageMission（覆盖契约）** | 人类向系统下达的正式任务合同：明确涵盖的行业、标的公司清单及优先级、常驻核心研究课题、必交交付物清单、数据源采集规划、机器被授予的写入权限清单、必须等待人工裁决的检查点、以及资金预算上限。若需调整任务范围，必须显式发布新版契约。 |
| **ResearchPlaybook（投研手册）** | 顶级基金分析师培训手册的合同化代码版本：规范了从初筛到持续覆盖的六个进阶阶段、每个阶段的必读材料与必交成果、出口质量把关问题、交付物标准模板、财务建模纪律以及风险回报评估标准。 |
| **阶段账本** | 记录每家标的公司在投研手册各个阶段推进状态的权威账目，状态仅包含三种：“已进入该阶段”、“已通过该阶段评审关卡”、“未通过评审关卡”。 |
| **Deliverable（投研交付物）** | 带有版本追踪的正式投研文档：包括初筛报告、公司深度档案、多空争议地图、行业分析框架、财务预测模型与投资备忘录。每个版本均忠实记录改版理由与触发该次改版的底层新事实。 |
| **WorkOrder（执行工单）** | 系统调度引擎向底层计算子进程派发的最小独立任务单元，附带明确的待解决问题、开销预算限制与防重复执行标识。子进程单方面汇报“执行完成”绝不等于通过了系统的质量核验。 |
| **Connector（数据连接器）** | 访问特定外部数据源的合规通道。每项具体操作均受到独立的人工治理审批控制：例如，批准抓取行情数据绝不意味着系统被允许读取财报日历接口。 |
| **ResearchEvent（研究事件）** | 全系统统一的外部动态登记入口：涵盖标的股价异常波动、新财报入库、新核心事实生成、财务对账完成以及关键日历到期。 |
| **五词决策体系** | 系统对任何市场动态事件进行影响评估时，最终结论只能且必须归入五个标准词汇之一：**维持当前观点（NO_CHANGE）、投资论点强化（THESIS_STRENGTHENED）、投资论点削弱（THESIS_WEAKENED）、投资论点打破（THESIS_BROKEN）、衍生新论点（NEW_THESIS）**。 |
| **独立交叉复核** | 系统起草的每一份重要研究交付物，必须由与起草模型属于不同技术厂商的大模型进行批判性交叉审核。厂商身份从底层的路由决策中动态读取，若无法判定为独立厂商，成果严禁发布入账。 |
| **专项预算池** | 单日资金预算被强制切分为四个相互隔离的专项资金池：日常核心覆盖池、事件即时响应池、专项深入研究池与系统日常维护池。某项资金池额度耗尽后，对应业务车道当天自动挂起，绝不挤占其他核心流程。 |

## 6. 研究手册：六个阶段与出口门

系统内置的投研手册源自专业基金内部的新员工培训教程，并于 2026 年 9 月 2 日被转译为机器刚性执行的代码合同。它严格锁定了投研推进的六个先后阶段；任何试图颠倒阶段顺序、绕过人类审核关卡或弱化数据穿透纪律的行为，都会被底层规则直接拦截。

```
Initial Screen ──► Deep Insight Gate ──► 行业模型 ──► 公司全模型 ──► Investment Memo ──► 持续覆盖
 （初步筛选阶段）      （深度认知关卡）                                    （正式投资备忘录）
  机器客观自检 4 问     人类亲自裁决 12 题     机器客观自评    机器客观自评       人类终审把关 4 问     无终态长期跟踪
```

| 投研阶段 | 规定必须研读的材料 | 规定必须提交的成果 | 出口质量评审标准（关卡把控点） | 最终裁决权归属 |
| :--- | :--- | :--- | :--- | :--- |
| **Initial Screen<br>（初步筛选阶段）** | 过去 4 个季度的官方财报与电话会纪要、最新年度 10-K 报告、近 6 个月多方与空方券商研报、产品与用户反馈。 | 简易损益测算模型、核心业务驱动因子梳理、初步投资假设论点、对同业其他标的的传导含义、潜在风险回报测算、七个章节的标准初筛报告。 | **客观自检四问**：<br>1. 资料底座是否齐全？<br>2. 正文每个时效数字是否精确穿透出处？<br>3. 是否提炼出足以实质驱动基本面的核心因子？<br>4. 是否清晰阐明了市场共识盲点、组合影响与风险回报比？ | 系统根据刚性规则自动自评 |

| **公司全联动财务模型** | 过去 2 年全部定期披露文件、近 3 年买卖方主流研报、历史重要经营数据专项公告。 | 历史标准化三张表联动、3 至 5 个核心驱动因子的情景敏感性测算、与华尔街卖方一致预期的核心分歧测算桥梁、前瞻财务预测线。 | **客观自评三问**：<br>1. 历史真实数据是否与申报文件 100% 勾稽一致？<br>2. 核心假设的逻辑推导是否逐条写明？<br>3. 与市场共识的预期差是否已完成量化拆解？ | 系统自动自评 |

| **持续覆盖阶段** | 最新监管申报公告、定期业绩快报、管理层指引更新、卖方评级异动、第三方另类跟踪数据。 | 每一个市场新动态均与模型驱动及核心论点完成因果映射，输出五选一的影响决策；定期输出业绩前瞻与财报后对账复盘；月度归零盲审。 | 本阶段为长效跟踪机制，无最终终止态。系统以“连续四周无漏报重复事件、无静默失败故障”作为稳定运行标准。 | 核心论点的每次重大修订提案均须人工一键裁决 |

### 关键细节阐述：
- **初筛阶段的“估值水平”章节坚决不由机器盲目起草**：因行情数据与卖方一致预期数据接口的正式治理审批尚未签署，系统严格恪守“缺就是缺，绝不脑补填数”的铁律，在未接入权威行情源前直接标注缺口，杜绝推算虚假估值。
- **阶段流转遵循绝对单向门槛（$k-1 \to k$）**：进入后一阶段的前提是前一阶段的出口关卡已确权通过。“深度认知门”和“投资备忘录”在代码层面、治理层面与数据库底层均被设置为**仅接受人类唯一合法身份签名**，系统自动化进程被彻底剥夺了自我审批过门的权限。
- **日常跟踪并不等同于进入了“持续覆盖阶段”**：标的公司只要通过了“初步筛选”，后台就会自动为其启动日常事实巡检；而该标的离开系统视野的唯一合法途径，是人类主动在任务契约中将其剔除出覆盖名单。

## 7. 研究交付物：机器到底能产出什么

以下梳理的所有研究资产，在当前系统中均已具备完整的数据结构、持久化写入车道、控制台展示界面与自动化测试用例验证（其实际生产进度详见第 12 节，请客观理解“具备该生产能力”与“已全量生成完毕”的边界）：

1. **初步筛选报告（Initial Screen）**：全面整合活跃事实库、SEC 报表数据、核心假设与产业链传导逻辑，自动起草为标准的七个章节。报告正文中的每一个财务数字必须强行回溯至一条定量事实，否则整节内容将被安全机制直接作废。起草完毕后，系统自动对照四项出口准则进行自评打分。
2. **公司全景深度档案（Company Dossier）**：针对单家公司的十个专题深度档案：商业模式、分部业务、需求动因、成本与交付、竞争壁垒、资本配置、业绩指引风格、非准则指标口径、潜在催化剂以及估值分歧点。其中需求与成本两节的框架由行业因果逻辑硬性派生，模型只负责基于事实填充内容，无权自行随意发明篇章结构；且正文每一句话均带有精准引文出处。档案只有在吸收了此前从未引用过的新证据时，才被允许晋升新版本。
3. **多空博弈争议地图（DebateMap）**：清晰回答“市场共识在哪、我方立场在哪、后续有何路径能够验证”。每一项争议条目必须对称呈现“市场多头立场”与“我方（或空头）反向论据”，状态流转包含“候选、开放讨论中、预期正在转向、已由事实证实或伪证”。若某一观点仅有一家券商提及，系统仅将其列为“候选线索”，不轻率定性为市场主流争议。
4. **深度认知门答卷（Deep Insight Gate Draft）**：版本化起草 12 项高阶投研问答。系统允许在某一题中如实填写“当前信息未知”，但必须同时说明需要何种证据才能消除该盲点。若第一题中的企业商业模式分类与公司档案记录不一致，整份答卷直接判定无效。
5. **行业分析框架（Industry Framework）**：产业链各传导环节逐一成节，长短期驱动因素深度绑定行业驱动因子包；五家标的公司的横向对标矩阵由底层算法直接导出（单元格精确标注底层文档编号，不可比指标明确提示口径差异）；系统还会自动推导出权威“数据源缺口清单”，这份清单正是后续向管理层申请采购新商业数据库的客观依据。
6. **财务模型规格与动因预测线（Financial Model & Drivers）**：首先由大模型制定“该标的应当如何构建财务模型”的规格说明（界定哪些是报表历史行、哪些是假设外推项、核心业务动因是什么）；随后由确定性算法从 SEC 报表底稿中自动推导历史实际数与预测线。测算全程采用高精度数值格式，多次重算结果逐字节严格一致。一旦实际财报出炉，历史预测值原地保留并显式标注“已被实际值取代”。模型必须通过**六项经济学不变量检查**（方向一致性、历史区间合理性、比率定义域合法性、分部加总勾稽、报告期间对齐、数值解收敛性），一旦失败整表作废，绝无人工特权放行通道。
7. **敏感性测算与一致预期桥梁（Sensitivity & Consensus Bridge）**：按照“若将某一核心业务驱动因子置于其历史极值（波峰或波谷），公司底层盈利将产生多大偏离”对假设重要性进行敏感性降序排列；同时将模型自测结果与卖方一致预期进行桥梁拆解（至少综合两家以上不同券商的预测，数据不足时严谨标明缺口）。
8. **专业 Excel 财务模型与 HTML 研报导出**：提供只读模式的导出能力。导出的 Excel 涵盖五张标准工作表（估值、财务三表、驱动因子、数据出处追踪、公式映射表）。唯有能够被系统底层翻译为合法数学等式的单元格，才会被导出为真正的 Excel 动态计算公式，并与系统底层的权威测算值严格比对验证；不支持公式化推导的格子则保持留空并记录于说明中，坚决不向表格内回填静态死数据。导出的 HTML 报告亦完整保留所有数据的引文出处、版本指纹、未决事项说明与审批留痕记录。
9. **正式投资备忘录（Investment Committee Memo）**：涵盖十二个标准篇章与十二个投委会核心关切问题，经历四轮严密的起草流水线与一轮跨厂商模型的对抗性复核。起草的前置输入必须包含人类此前已亲自批准的深度认知答卷、公司深度档案、行业分析框架、全套联动预测模型与敏感性分析。人类投资总监签字批准后，系统自动将标的流转进入“持续覆盖阶段”。
10. **日常动态跟踪与五词影响研判**：行情异动、新财报公告、新提炼事实、对账偏离以及关键日历到期，均统一收敛登记为标准研究事件。每一个事件均触发一次严格受控的模型研判，输出五选一的标准决策词汇，并留下完整审计痕迹。跟踪频次由策略统一锁定，涉及股价、SEC 披露与重要日历的监控频次被硬性规定，机器无权自行降低频次。
11. **财报季前瞻与业绩对账校准（Earnings Preview & Review）**：公司发布财报前 30 天，系统自动起草业绩前瞻报告（拆解市场共识预期与我方预测的核心看点）；财报公布后 48 小时内，系统自动执行对账校准——首先由确定性算法将历史预测格子替换为实际申报值，分三档计算对账偏差，将管理层最新指引与实际表现逐一核对；随后发起一次模型调用撰写定性归因分析并给出五词结论。未来期间的预测假设在此刻保持一格不动，防止逻辑混乱。
12. **催化剂动态日历（Catalyst Calendar）**：外部行情源提供的往往是“预估业绩日期”，而 SEC 8-K 披露的则是“官方确权日期”。当两项数据存在偏差时，系统同时完整保留并清晰标注属性，绝不机械地拉平均值掩盖分歧。
13. **高置信判断提案（Conviction Call）**：专为挖掘非共识超额收益而设。启动该模块前必须通过三道刚性前置闸门（标的具有生效中的核心论点、在某项核心争议上与市场共识针锋相对或预期差达到设定阈值、市场共识看法具备确凿引文出处）；只要有一项不满足，系统连模型都拒绝调用。该模块只能以“提案”形式呈送人类，由人类最终拍板采纳、驳回或搁置。
14. **周度研究简报与运行审计复盘**：周报围绕“覆盖进度推移、新增认知提炼、财务预测变更”展开编制；周度复盘模块则完全基于确定性账本进行统计，不调用大模型、不修改任何业务数据，只客观向基金经理呈现：“本周投研团队的算力与时间花在哪些地方、未决研究课题是增加了还是减少了、有多少研究成果尚未完成质量评估”。
15. **投研质量客观评估（Quality Rubrics）**：内置四套冻结的质量评分量表（涵盖初筛、即时问答、公司档案、研究周报），分为确定性合规初检与有界定性判读两层，评分模型必须强制与起草模型分属不同厂商。人类分析师亦可通过内置的标准反馈动作（已阅 / 采纳 / 论据不足 / 观点存疑 / 建议重拟）对成果进行评价，系统严格只接受具备合法签名的人类反馈。
16. **基于事实底座的即时深度问答（Grounded Ask）**：问答引擎检索整合了包括公司档案、争议地图、预测线、卖方一致预期、催化剂日历、近期事件与历史复盘在内的十三个专业上下文数据块；若某一块数据缺失，系统会明确报告原因。回答内容必须经受七道确定性逻辑质检，“市场对我们”的对比格局必须逐项填满。一次完整的深度推演问答目前在后台耗时约一分钟。

## 9. 系统每天是如何自主运转的

以当前系统线上常驻运行的实战任务为例：**美股 IT 服务行业（US IT Services）首次覆盖**，涵盖五家全球龙头标的：**埃森哲（ACN）、高知特（CTSH）、EPAM、IBM、DXC**；确立了四个常驻核心研究课题（行业整体需求是否见底、AI 转型能否有效对冲传统咨询支出下滑、五家公司核心指标分化的根源为何、市场当前的隐含预期与我方的判断存在何种预期差）。

调度核心进程（controller）每隔数秒跳动一次（tick），每一次跳动均会按照严格注册的流水线顺序对各项研究任务进行全量巡检。在一个典型的日常周期内，系统依次自主推进以下事务：

1. **第一步：核验资料底座是否齐全。** 系统针对覆盖名单中的每家公司，对照手册必读材料清单，逐项核算“已具备 / 仍缺失 / 来源不可用”的真实状态（包括近 4 个季度官方财报、近 4 场业绩电话会速记、最新年度 10-K 报告、近 6 个月多方与空方研报）。若检测到某标的缺少某特定季度的电话会纪要，系统便会精准生成针对该季度的定向搜索与采集指令。
2. **第二步：合规搜集与原文抓取。** 系统按照标的公司的商业优先级与文献类型（电话会与年报享有最高优先级，财经新闻处于次级），受控向 AlphaEngine、SEC 接口以及公开财经网站发起定向检索与抓取，严格受制于单日配额限制。所获取的一切文献在进入处理前，首先在本地计算并生成不可篡改的数字指纹，封存为原始归档文件。
3. **第三步：深度研读与事实入库。** 系统调用高通量轻量大模型，逐段分卷精读原始文献，提炼出候选定性事实，并为每句话牢牢绑定精确到具体字节的原文出处；随后通过策略规则审核准入为正式事实。SEC 申报的财务报表行在通过跨表勾稽校验后，作为定量事实入库。若检测到错误归属或套用免责声明的事实，系统会自动启动退役流程将其清除出生产环境。
4. **第四步：自主起草与对抗性复核。** 当某家公司的资料底座满足基本条件后，系统自动触发起草流水线，编纂初步筛选报告、公司全景深度档案、多空争议地图以及财务模型规格说明；起草完成后，必须自动交由另一家技术厂商的大模型进行批判性交叉复核；未通过逻辑核验或缺乏证据支撑的成果草案不会被盲目重复试错，而是直接归入控制台的“异常待办中心”并清晰注明卡点原因。
5. **第五步：质量过门与阶段晋级。** 初筛报告起草完毕后，系统对照手册内置的四项出口质量准则进行客观自检自评。一旦四问全部通过，该标的正式晋级进入常驻跟踪阶段，系统随即开始自动梳理“深度认知门 12 问”的详尽答卷，呈送给人类分析师等待决策。
6. **第六步：日常事件跟踪与五词研判。** 外部市场一旦涌现出新抓取的财报数据、新提炼的关键事实或股价出现异常波动，系统立即登记为标准研究事件，由认知引擎逐一评估其对核心投资论点的影响深度，输出标准的五词研判结论并记录在案。
7. **第七步：周度简报与资源复盘。** 每周定期生成一期正式的投研综合简报，同时系统自动生成一份关于算力开销、任务完成率与未决问题存量的审计复盘报告。

在整个端到端推进过程中，人类分析师完全无需紧盯后台代码或任务队列，在控制台的日志视窗中，您只会看到一行行清晰、专业的业务推进提示，例如：“正在为 ACN 补全 FY2026 Q3 业绩电话会纪要”、“已成功退役 49 条误归属事实”、“ACN 初步筛选报告第一版起草完毕，出口自评得分 3/4，当前主要缺少关于市场预期盲点的论述”。

## 10. 操作指南：控制台与日常交互

### 10.1 系统提供的两个访问视窗

- **分析师交互主控台（Interactive Cockpit）**：在已获授权并接入 Tailscale 安全局域网的设备上，直接访问专用加密地址。这是分析师进行日常阅读、方向指引、深度提问与审批操作的完整业务入口。
- **公开只读监督看板（Public Read-only Dashboard）**：为团队管理层提供的只读状态页面。定期刷新呈现全局覆盖进展、近期系统动态、大模型费用消耗以及最新研究资产生成情况，该视窗无法打开个股深度详情、不支持交互提问与成果下载。

### 10.4 新建与切换独立研究环境

在「研究环境」中输入名称并新建。系统自动准备数据库、模型运行配置、宿主已登记的数据源连接、研究手册和后台服务。进入新环境后，写下研究目标，核对系统整理的公司、问题、资料范围和预算，确认后开始研究。无需为每个环境重复登记模型和 connector，也无需运行安装命令；目标含糊时，页面会提示补充研究范围。运行时仍会检查连接状态，并按原有规则处理上游不可用或限流。

每个环境都有自己的研究目标、公司、任务、资料、结论、审批、调用账本和后台进程。模型网关、connector 服务、账户连接以及同一版本的程序和依赖共用。新环境保持研究内容为空，不复制其他环境的研究或历史审批。

切换环境只改变正在查看的页面。原环境的任务继续执行，关闭浏览器也不会停止后台研究。同一公司可以在多个环境中分别研究，各自形成独立的资料、判断和审批记录。共享供应商的限流仍适用；任务达到本环境预算或等待供应商额度时，按原有重试和预算规则处理。

## 11. 模型选择、预算分配与运行成本

### 11.1 三档推理模型路由阶梯

系统在设计上为不同性质的投研计算环节，匹配了不同能力特征的大语言模型，构筑了三条有序调用的模型链：

| 算力推理档位 | 对应的核心投研业务环节 | 当前系统配置的模型路由链（主选优先级 ➔ 备选优先级） |
| :--- | :--- | :--- |
| **高阶复杂推理档** | 撰写逻辑研判、全局任务排程规划、高质量起草长篇投研文档、深度即时穿透问答 | `gpt-6-astra` ➔ `claude-fable-5-1` |
| **高通量高性价比档** | 长文分段精读、信息抽取与结构化打标签、从海量检索结果中初筛有价值材料 | `deepseek-v4-flash` ➔ `zai-glm-5-3-flash` ➔ `gemini-3-5-flash-lite` |
| **独立对抗性复核档** | 深度交叉复核公司档案、多空争议地图、深度认知门答卷、正式备忘录、业绩对账结论 | **必须且强制与起草模型分属不同技术厂商**；当前生产环境指定调用：`gemini-3-8-flash` |

系统在模型调用上拥有极强的错误处理纪律：只有在遭遇底层网络传输故障、API 供应商服务中断或模型完全不可用时，系统才会自动降级至备选模型继续执行；若遭遇的是内容审核拦截、资金预算超限或违反系统契约规范，任务会在原地直接挂起并如实上报，**绝对严禁暗中切换其他模型强行重试**。系统每一次对模型的选择、重试与故障转移，都会在底层沉淀为一条不可篡改的路由审计记录。调整各环节的模型分配完全无需修改源代码，分析师可在控制台的“模型与预算”板块中直观调整，支持热加载的环节在下一次调用时即刻生效。

### 11.2 资金预算与风控配额

- **单日总预算与预算池**：当前美股 IT 服务研究环境的授权为每日总计 180 美元，其中持续研究 100 美元、事件响应 50 美元、专项研究 25 美元、维护 5 美元。预算及已用额度按研究环境分别记账；在控制台保存研究预算时，系统自动同步任务、研究授权和付费准入策略，并保留已用额度，无需手动逐项修改。新环境在确认研究目标时展示自己的预算。
- **单次调用配置**：单次模型费用上限默认 1 美元，由宿主共享配置统一管理。在任一环境修改某个调用用途的费用上限后，已有环境的下一次同用途调用和未来新环境自动读取同一策略，无需逐个修改模板。运行中的 planner、thesis 服务、文档读取及诊断预览共用这条配置读取路径；已经发出的调用保留原预算与费用记录。输入、输出 Token、超时和每轮批处理预算仍按环境配置，日预算照常限制实际支出。
- **外部数据接口调用配额**：各数据供应商接口亦配置了严格的保护策略，例如 AlphaEngine 设定为每 24 小时最大 130 次调用，SEC 申报索引设定为单日最多检索 200 次。
- **开销前置鉴权**：在实际发起计费调用之前，系统会强制核查任务合同授权；若某项业务操作未在合同中被授予写入权限，系统连一次模型调用都不会发出，并将“未获授权”状态直接呈现在控制台界面中。

以下为历史运行样本，不代表当前预算设置或当前研究吞吐。以 2026 年第 36 周为例，整整一周系统仅消耗了 0.03 美元、发起了 19 次计价调用，占周度预算上限的比例不足 0.1%。周度复盘报告中对此做出了客观的诊断：“资金预算并非系统的发展瓶颈，研究产出偏少的主因在于上游数据源授权与底稿断流，单纯提高资金上限无法促使系统产出更多成果。” 在实测中，一份标准初筛文档从零起草至最终过门，消耗的模型算力费用目标被牢牢控制在 0.2 美元以内；一次涵盖 13 个上下文模块的完整深度问答，实测开销约为 0.32 美元。

### 12.4 语言与可读性修复的历史背景（09-13）

基金负责人在深度审阅了当前线上系统的全部 101 个页面状态后明确指出：暂停一切高阶功能的横向拓展，必须首先把控制台界面改造为“受过正常良好教育、具备基础金融知识的人能够轻松读懂、顺畅操作”的专业形态。当前界面暴露的问题主要包括：底层英文异常报错与系统长编号直接泄漏在主界面上；出现诸如“证据变厚了”、“看街上预期什么”等严重脱离金融实际的生硬机翻；每股收益（EPS）被按百万美元统合缩放导致全表显示为荒谬的 0.0；“今日事件”列表未对时间范围进行准确限定；问答模块将 DXC 的模型数据混淆为 IBM；审批工作台中的 49 条待办事项里有 42 条属于重复积压的历史关卡重开请求；结论事实列表在展示至 300 条时存在静默截断且缺乏分页提示。

目前的整改方向极为明确：所有面向用户的最终研究交付物与界面文案必须转换为地道、优雅、专业的简体中文（Excel 财务模型底稿可根据机构惯例保留标准英文科目）；所有财务指标的数值展示必须严格遵循金融学常规计量单位换算；坚决剔除诸如“不是 / 不能 / 不作为”等冰冷拖沓的防御性程序员说辞；所有成果在正式发布前必须通过一道专门的语言可读性审核。这批改进已包含在 09-14 部署中；此处保留最初的问题与整改要求。

### 12.5 经论证后明确冻结或彻底放弃的技术方向

- 大模型自主编写新技能并置于沙箱中自我演化；
- 以纯向量数据库检索（Embedding-first）作为底层核心架构；
- 引入重量级的第三方分布式工作流调度框架（如 Temporal）或通用数据库系统（如 PostgreSQL）；
- 多种复杂跨平台运行时的架构重写；
- 复杂的长任务任意中断与中途恢复机制。

上述技术设想曾出现在早期的架构草案中，经过严密的技术论证与真实投研实战检验后，已被正式确认为不符合买方投研实际需求的“过度工程设计”，已全面予以冻结或放弃。

### 12.6 后续推进的标准业务顺序

当前优先完成已获取材料的自动阅读与研究阶段推进，持续核对模型失败、资料缺口和实际交付物。新增环境复用已部署的研究引擎；后续新增功能按研究需要推进，授权和审批仍使用各环境自己的记录。

> - **“分析师面对的应当是研究组合与认知成果，而不是杂乱的底层任务队列。”**
> - **“切忌将原本用于阶段性验收的人工把关动作，异化为拖垮生产力的冗长日常审批流。”**

> - **“版本化是一种底层的留痕演进机制，它本身绝不充当盲目修改的触发器。”**
> - **“市场看多你也看多、市场看空你也看空，没有任何信息增量。真正有价值的是要想明白：当前资本市场的共识究竟在哪个环节出现了定价错误。”**
> - **“沉淀的历史资料只是接受合规治理的数据源，资料堆砌本身绝不等于研究认知。”**
> - **“在经过严密逻辑论证的前提下，审慎地维持既有观点不变，本身就是极其宝贵、高质量的研究产出。”**

## 14. 代码仓库结构与开发者入口

系统代码托管于主代码仓库 `dalton-research-agent-os`，当前核心活跃开发分支为 `continuous/0913`。

| 目录模块 | 承载的核心业务与技术内容 |
| :--- | :--- |
| `src/dalton_core/` | 系统的绝对控制中枢。包含约 450 个核心 Python 模块、30 万行经过严密测试的代码，采用清晰的扁平化包架构。内部严格按照约定成俗的架构模式解耦：针对外部数据源，统一步署包含“身份治理、数据归一化、子任务接入点、安全启动器、业务驱动车道”的标准五件套；针对研究交付物，统一步署包含“权威数据定义、自主起草引擎、子进程执行器、启动器、业务车道”的标准五件套。 |
| `contracts/` | 172 份跨进程通信的 JSON Schema 强类型契约，严格规范了数据连接器接口、系统能力治理、事实账本结构、研究计划模型、大模型路由调度、底层写入操作、自然语言意图编译、以及覆盖任务契约与最终交付物格式。 |
| `deploy/macos/` | 生产环境专属的安装初始化脚本、自动化健康巡检探针、以及环境卸载清理脚本。 |
| `deploy/phase9/` 等 | 版本化归档的各项核心业务契约：包括投研手册规范、覆盖任务契约、数据源采集排程以及各类运行风控策略的正式 JSON 定义。 |
| `deploy/connector-governance/` | 针对每一个外部数据源以及每一项具体抓取操作的人工治理审批留痕档案。 |
| `integrations/` | 桥接 OpenClaw 网关的模型认证经纪人以及网络搜索插件（基于 Node.js 编写），严格确保所有第三方账号凭证完全封存在宿主环境中，杜绝泄露风险。 |
| `tests/` | 单元与集成测试，默认使用隔离状态和模拟适配器；真实供应商调用由单独的验收流程明确发起。 |
| `scripts/` | 系统运维、发布与质量验收脚本，包括在隔离环境中复现业务逻辑的演练脚本（Canary）。 |
| `docs/adr/` | 9 份正式沉淀的系统架构决策记录（ADR），记录了核心技术路线的取舍理由。 |
| `docs/reports/` | 阶段性投研进展、发布验收与架构审查报告，记录各自对应时点的开发认知与环境状态。 |
| `docs/PROJECT_STATUS.md` | 记录每一个检查点与版本迭代的权威进度档案，顶部始终展示最新生产状态。 |
| `SPEC.md` | 规定系统全貌与技术边界的完整技术契约规格说明书。 |

在本地隔离环境中进行全套自动化验证仅需执行以下标准指令：

```bash
# 1. 采用编辑模式安装核心运行时
python3 -m pip install -e .

# 2. 运行全量自动化测试套件
python3 -m unittest discover -s tests -v

# 3. 运行无网络依赖、不产生任何外部模型开销的投研认知闭环演练复盘
python3 scripts/run_hermetic_research_replay_canary.py
```

## 结语

在买方投研全面拥抱 AI 浪潮的今天，决定一家投资机构长期核心竞争力的，绝非“谁更会向通用对话框写 Prompt”，而是**“谁能够构建起一套将浩瀚市场信息沉淀为深度基本面认知、将大模型严格约束在严密金融常识与财务证据链之内、并让人机无缝分工协作的现代化投研基础设施”**。

Dalton Research OS 正是为践行这一崇高愿景而诞生的严肃探索。它让计算机承担起最耗时的大规模文献搜集、事实核验与财务勾稽，让人类投资经理全身心沉浸于商业逻辑洞察、预期差甄别与组合风险下注——这是一套真正属于数字时代的顶尖买方基金“外挂认知大脑”。
