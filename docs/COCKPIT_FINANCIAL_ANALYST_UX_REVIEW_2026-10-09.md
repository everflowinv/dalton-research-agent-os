## 一、 执行摘要与核心价值观重塑

当前 Dalton Cockpit 虽然完成了由 v1 向 v2 的架构重构，并尝试进行了中文替换，但**本质上依然是一套“由工程师设计给工程师维护 AI Agent 的后台管理控制台（DevOps / Admin Panel）”，而不是一套“服务于金融行业买方投资决策的专业投研工作台（Institutional Research Workbench）”**。

### 核心矛盾分析：

| 维度 | 现有系统的开发者思维（现状） | 金融分析师的真实业务诉求（目标） |
|:---|:---|:---|
| **信息层级** | 堆砌大量的流水线状态、工单完成度、Token 预算消耗、抽取失败率、缓存命中 | 核心投资论点、预测差异（Variant View）、估值倍数（P/E, EV/EBITDA）、盈利拐点、催化剂日历 |
| **语言体系** | 裸露底层架构：`service.json`、`bounded_planner`、`us-gaap:...`、`CIK 0000789019`、`SHA-256`、`微秒(micros)`、`改绑票据` | 标准金融术语：营业收入、经调 EBIT、一致预期偏离度、基准/悲观/乐观情景收益率、估值折现 |
| **交互逻辑** | 任何轻微操作（甚至包括“已知悉通知”、“暂不提醒”）都弹出输入框强制要求写 600 字理由；操作缺乏撤销与确认边界 | 极简、高效、非阻塞。分析师需要快速浏览、直接调整情景概率（拖动或填数字即生效）、一键导出 Excel/PDF、平滑追问 |
| **视觉呈现** | 页面大面积使用等宽纯文本（`<pre>`）展示复杂财务预测表；表格无千分符、无粘性表头；颜色红绿混乱（反向运用涨跌色） | 严谨的现代金融表格（右对齐、三位千分符、以“亿美元/百万美元”为单位）、清爽的财务走势双轴折线、标准杜邦/利润瀑布图 |

## 二、 全系统高频通用痛点深度剖析

### 2.1 严重劝退金融分析师的五大“致命体验硬伤”

#### 🚨 痛点 1：极端反人类的“全员写理由”交互摩擦力
在 `task_entry.js`、`scenario_edit.js`、`policy.js`、`templates.js`、`admin.js` 中，开发团队为了实现审计留痕，实现了一个通用的 `reasonForm`。其后果是：
- 分析师在待办列表中看到一条系统提示，想点击**“已知悉”**关闭提示，系统立刻弹出一个大框，红字标明：**“理由（必填，会和操作一起存档，最多 600 字）”**！分析师不敲一堆字，连关掉一条已读消息都做不到！实测线上数据库里用户被逼无奈只能输入“知道了”、“111”来敷衍提交。
- 调整三个情景的概率，填完 50/30/20，下方必须输入“调整理由（必填）”；
- 换一个 Excel 导出模板，必须输入“指定理由（必填）”；
- 重新跑一次翻译，必须输入“重新进行语言质检理由（必填）”。
> **严重定性**：这不仅极大地破坏了操作流畅度，更让金融分析师产生“被系统审问”的强烈烦躁感。

#### 🚨 痛点 2：随时随地引发焦虑的“算力与计费恐慌”
在分析师本该专注研究的界面上，充斥着大量的技术成本恐慌性文案：
- 研究问答输入框下常驻警告：*“回答只使用本项目已整理的资料，会产生一次 AI 调用费用，通常需要约一分钟。”*
- 问答回答卡片底部显著标注：*“本次 AI 费用 US$0.02 · 沿用上次结果未再计费”*。
- 调整研究方向按钮下警示：*“上面还有一份没有确认的草案；重新整理会替换它，并再产生一次 AI 费用。”*
- 任务卡片确认按钮弹窗：*“确认？丢弃缓存的译稿，从头起草，会花一次起草和质检的模型费用。”*
> **业务认知脱节**：机构金融分析师每天调动数百万甚至数千万美元资金进行投资决策，其时间价值远高于几美分的 API 调用费。页面不应该像“网吧计时收费器”一样时刻向分析师敲打零碎开销，这在买方机构看来既廉价又制造无谓的决策顾虑。

#### 🚨 痛点 3：极具金融合规风险的底层概念机翻（“再买一次”）
在 `task_entry.js` 的 `doorsBox` 恢复动作中，后台代码暴露了如下按钮文案：
- **`放行一次重新进入` / `再买一次` / `撤回`**。
> **金融合规灾难**：在股票投研软件中，**“再买一次”（Buy Once More）** 具有极端敏感的交易含义！任何基金经理看到这个按钮的第一反应必定是：*“点击这个按钮难道是在经纪商交易端追加买入该股票头寸？！”*。而实际上，后台程序员的意思是“再向第三方 API 付费买一次专家纪要或 Token 额度”。这种用语在金融软件中属于重大定级事故。

#### 🚨 痛点 4：核心财务报表退化为等宽代码块（`<pre>`）
在公司详情的【财务模型】(`companies.js:498`) 中，系统的核心预测输出居然是：
```html
<div class="v2-table-wrap">
  <pre class="v2-pre">Revenues: 18044066000 ...</pre>
</div>
```
- 直接把后台 Python 打印的 80 列等宽纯文本直接塞给用户；
- 页面无法固定首列（科目名称），横向滚动时，分析师根本看不到当前行是“营业利润”还是“业务优化费用”；
- 金额数值裸露为未格式化的 `18044066000` 或 `18988657262.99874490`，无分节符、无单位对齐；
- 甚至在科目名称中出现：“本行为收入（Revenues）科目。”等代码生成器注水文字。

#### 🚨 痛点 5：机械门禁导致系统假死感与大面积“检查文字”占位符
当大模型质检环节未通过或处于 pending 状态时，前端粗暴地将所有正文、甚至整张卡片替换为：
**“正文正在检查文字表达，完成后会显示。”**
- 在分析师看来，页面就像是“白屏崩溃”或“被系统风控封锁”，完全不知道后台在干什么，更不知道预计何时能看；
- 在【待我处理】中，有整整 6 张积压卡片反复提示：*“一批界面文字的中文翻译停下了：已连续失败 6 次，系统不会再自动重试……原因：independent localization verifier did not pass cleanly”*。分析师完全被抛在技术报错的迷宫里。

### 2.2 视觉与审美缺陷（为什么“看起来不像专业金融终端”？）

1. **“大卡片套大卡片”导致信息密度极其低下**
   - 现代金融终端（如 Bloomberg, FactSet, Wind, 标普 Capital IQ）要求在 1080P/2K 屏幕上高效组织高价值信息密度；
   - Cockpit v2 普遍采用 `18px` 大圆角、内衬 `24px` padding、外加层层 `details/summary` 折叠，大量珍贵的首屏空间被浅灰色背景块和装饰性空白吞噬。分析师打开首页，首屏只能看到 1~2 个公司卡片。

2. **配色缺乏金融严肃性与语义倒错**
   - 按钮大量混用深紫 (`--v2-grad-b`)、亮青 (`--v2-accent: #3ee0c8`)，风格偏向加密货币 Web3 或极客控制台，缺乏传统买方机构所信赖的稳重与权威感；
   - 涨跌/正负颜色定义冲突：在金融图表中，国际惯例是绿色代表上涨/收益（正）、红色代表下跌/亏损（负）（国内A股则反之）。而在部分图表和卡片中，收益率被写为中性灰色，反而将“待处理”或“预算受限”使用了大面积高亮红黄色，造成视觉干扰。

3. **图表（Charts）缺乏金融专业表达**
   - 财务模型图表只把历史与未来连成两条折线，缺乏置信区间阴影带；
   - 关键指标缺乏历史估值分位数带（PE Band / PB Band）；
   - 利润瀑布图（Waterfall）负项与正项在不同模式下的色块区分模糊，且图表下强制重复堆砌“查看数据表”折叠区，造成视觉混乱。

### 2.3 语言与文案缺陷（代码裸露、生硬机翻、算力恐慌）

| 严重程度 | 页面出现的位置 | 现有界面原文字样 | 分析师读到的感受 | 推荐重构后的专业金融表达 |
|:---|:---|:---|:---|:---|
| **P0 严重** | 待办处理卡片操作 | `放行一次重新进入` / `再买一次` / `撤回` | 极度恐慌：“系统是要在交易市场追加买入股票吗？！” | **`恢复任务并重新抓取` / `放弃补充该资料`** |
| **P0 严重** | 待办处理卡片标题 | `publication-parked:ui-text-batch:...`，`independent localization verifier did not pass cleanly` | 乱码报错，系统崩溃了，充斥英文代码堆栈 | **`部分研究结论中文译稿待人工复核`** |
| **P1 显著** | 公司概览/估值 | 微软公司名称显示为 `0000789019`（SEC CIK 码） | 为什么公司名字是一串神秘数字代码？ | **`微软 MSFT`** |
| **P1 显著** | 财务模型/证据 | `us-gaap:NetCashProvidedByUsedInOperatingActivities` | 程序员把数据库里的字段名直接扔到屏幕上了 | **`经营活动产生的现金流量净额`** |
| **P1 显著** | 投资观点/决策 | `正文正在检查文字表达，完成后会显示。` | 占位符 Bug，报告损坏了 | **显示当前已有草稿，并打上标牌 `[初稿·校审中]`** |
| **P1 显著** | 情景与触发 | `否定条件 0/1 已出现`，`已出现的否定条件 1 个` | “否定条件”是什么中文？语病严重 | **`核心风险/证伪预警触发（1 项）`** |
| **P2 一般** | 规则配置比对 | `对比：左` / `对比：右`，`左`，`右`，`已改` | 以为在用 Git 代码比对工具（GitHub Diff） | **`基准版本` / `对比版本`，`变更明细`** |
| **P2 一般** | 报告模板上传 | `模板代号只能用小写字母、数字和连字符，例如 owner-tmt` | 强迫金融分析师学习正则表达式和 Slug | **系统后台根据模板中文名自动生成代号，隐藏该字段** |
| **P2 一般** | 项目切换与设置 | `service.json 的 bounded_planner 与现有环境不同，请先运行 reexport-runtime-templates-2026-09-30.sh` | 谁让我去服务器跑 Shell 脚本？！ | **直接提示：`该项目模板配置需要系统管理员维护更新`** |

### 2.4 交互逻辑缺陷（“全员写理由”的极端摩擦力与断头路）

1. **单向断头路，无法闭环**
   - 在【待我处理】中，提示某公司“缺少电话会纪要，请补充”，卡片上唯一的按钮是“去确认”或“查看公司研究”，点击后跳到公司概览页，但概览页上**根本没有任何上传或输入电话会纪要的地方**！分析师被引导了一圈，发现死路一条。
2. **缺乏多轮上下文的伪“对话”**
   - 【研究问答】标题宣称“问答”，但顶部提示赫然写着：*“每个问题单独回答，不会自动带上上一条问题的上下文；追问时请写清公司和期间。”*
   - 下方的“基于这条追问”按钮，仅仅是在输入框里机械追加文字：`关于「...」的回答：`！现代金融分析师习惯于 ChatGPT / Claude / Bloomberg GPT 式的多轮递进式调研，这种单轮无状态交互体验极其原始。
3. **脆弱的草稿与表单状态管理**
   - 虽然引入了 `sessionStorage` 暂存，但若分析师在未点击发布前切换了项目或页面，后台刷新接口时仍存在竞态覆盖风险；
   - 规则编辑器中，修改了十几个阈值后，如果不小心按了 `Escape` 键或者点了外部空白，缺乏明确的“内容未保存，是否确认离开？”拦截机制。

## 三、 全局框架与常驻组件 Review

### 3.1 顶栏（Top Bar）与项目切换器

```
[ Dalton 研究工作台 ]   [ 研究项目：美国 IT 服务研究 ▼ ]     ( 后台在线 · 3分钟前 ) ( 研究受阻 8 项 ) ( 数据更新于 10-09 11:04 )
```

#### 存在问题：
1. **项目切换下拉框位置与层级尴尬**
   - 下拉框使用原生 HTML `<select>`，在现代高分屏下样式粗糙，无项目元数据（覆盖了几家公司、当前有哪些重大待办）；
   - 当分析师在空白环境（8794）时，下拉框选项中出现“未命名项目”，缺乏初始引导。
2. **状态指示器（Pills）语义模糊且引发误解**
   - `后台在线 · 最近活动 X 分钟前`：分析师关心的是“我的研究数据是不是最新的”，而不是“Python 服务后台进程活着没活着”。
   - `研究受阻 8 项`：红色药丸常年常驻在顶栏正中央，给分析师造成极大的“系统故障”焦虑。点击跳转后，发现大部分都是“翻译重试了6次”这种无关紧要的后台日志。
3. **更新时间格式不符合中文商务习惯**
   - 显示为 `数据更新于 2026-10-09 11:04:36`，精确到秒并带浏览器时区说明，属于机械直出，信息冗余。

#### 建议修改方案：
- **项目切换重构**：将 `<select>` 升级为现代金融项目卡片切换菜单，显示项目名称、覆盖公司股票代码列表（如 `ACN, IBM, CTSH...`）、最新研报日期与待决投资决策数。
- **状态指示器精简重构**：
  - 正常状态显示：`● 投研引擎运行中 · 数据已同步至最新收盘`；
  - 异常状态分离：将技术服务报错彻底移入管理员视图，分析师端仅显示：`● 有 2 项投资决策待审批`。

### 3.2 左侧全局主导航轨（Left Navigation Rail）

```
[D] Dalton 研究工作台
  ├── 📊 研究总览
  ├── 🏢 公司研究
  ├── 💬 研究问答
  ├── 🔔 待我处理  [ 8 ]
  └── ⚙️ 研究设置
  ------------------
  [ ↩️ 返回旧版 ]
```

#### 存在问题：
1. **底部赫然保留【返回旧版】链接**
   - 作为一个成熟的 v2 系统，在分析师侧常驻“返回旧版”入口，传递了极度不自信的产品信号；更严重的是，点击“返回旧版”直接跳入充斥代码与哈希的 `/legacy` 废弃页面，造成体验断崖式下跌。
2. **导航命名与投研工作流不匹配**
   - 现有的“待我处理”容易被误认为是“系统运维任务待办”；
   - 缺少快捷的“行业/个股一览”或“投资备忘录研报库”直达入口。
3. **数字徽章统计口径错误**
   - 红色角标 `8` 统计了大量的后台报错（如 6 次翻译失败），而真正的“投资论点审批”可能只有 0~1 条，导致狼来了效应，分析师逐渐忽略角标。

#### 建议修改方案：
- **彻底移除【返回旧版】链接**，旧版彻底封存或仅限开发调试端口通过 `?debug=legacy` 访问；
- **重构导航命名与排序**：
  1. `投资总览`（宏观与行业核心图景）
  2. `公司研报与模型`（个股纵深研究）
  3. `研究问答`（AI 交互调研）
  4. `投资决策审批`（专管阶段门禁与观点裁决，仅统计需分析师决策的事项）
  5. `投研参数设置`（仅保留股票池、情景偏好与模板）

### 3.3 右侧常驻抽屉（Side Drawer `#v2-side`）

#### 存在问题：
1. **抽屉承载过多异构内容**：
   - 既用来展示简短的“来源与出处”，又用来展示上万字的“投资备忘录全文阅读”，还用来承载“本周复盘”和“研究轨迹”；
2. **标题与返回按钮逻辑割裂**：
   - 顶部只有一个固定的 `#v2-side-close` 按钮，文案僵硬地写着“返回公司研究”；当分析师在“研究总览”点击本周复盘打开抽屉时，按钮依然叫“返回公司研究”或“返回研究总览”，且点击后直接生硬卸载整个抽屉，无平滑滑动动效。
3. **研报全文阅读排版拥挤**：
   - 在 480px~600px 宽的侧边栏内硬塞三级标题、正文、未确认缺口、几十条引用来源，行高过密，分析师根本无法沉浸阅读长篇研报。

#### 建议修改方案：
- **分流抽屉职责**：
  - 轻量级信息（引用出处、字段定义）：保留为右侧快速滑出的 `Slide-over Panel`；
  - 重量级长文（投资备忘录全文、深度争论图谱）：升级为中心聚焦式 **沉浸研报阅读器（Focus Reader Modal）**，支持目录树导航、字号调节、一键复制段落与打印排版。

### 4.3 子标签 ①：【投资观点】(`view`)

#### 存在问题：
1. **备忘录摘要与初筛报告逻辑混杂**：
   - 页面代码 `readyText(memo) ? memo : readyText(screen) ? screen : null`。当备忘录未定稿时，降级展示初筛报告，但文案却写着 `来自初步研究筛查报告（草稿 · 尚未审核）`，并在下方显示“对初步研究报告留反馈”。金融分析师无法确切感知当前系统对这家公司的正式投资结论究竟是什么。
2. **“财务模型”状态行用语外行**：
   - 键值对中显示：`财务模型：完整三张表预测已建立，预测未来 8 个季度` 或 `财务模型：尚未建立`。
   - 实际上在买方研究中，分析师最关心的是：**“模型预测的 2026 财年收入增速与 EPS 是多少？与华尔街一致预期相比是高还是低？”**，只告诉分析师“表建好了”毫无决策参考价值。
3. **“关键数字”列表格式混乱**：
   - 出现 `（期间未注明）`、`原始名称: ...` 等未清洗内容；
   - 类似 `18044066000 USD` 的数字未转换为“180.44 亿美元”。

#### 逐按钮审计：
- **`[ 阅读投资备忘录全文 ]` 按钮**：样式为 `v2-btn-secondary`，灰色边框，视觉层级过弱。这是分析师了解该公司的最重要的入口，**必须升级为主行动按钮（Primary Button）**。
- **`[ 留反馈 ]` 展开按钮**：点击展开 5 个选择按钮（已阅读/有参考价值/证据不够/不同意这个结论/需要重写）。分析师不是众包标注员，这种给模型打标式的组件放在观点正下方显得极其业余，应收缩为右上角辅助操作或研报末尾的专业批注入口。

### 4.4 子标签 ②：【估值与回报】(`valuation`)

#### 存在问题：
1. **估值指标表格死板、缺少历史估值参考线**：
   - 罗列市盈率、市销率、EV/EBITDA 等指标，仅给出一个 `历史分位 45.2%`。
   - 专业的金融呈现方式必须包含：**当前值、3 年历史均值、+1 标准差、-1 标准差、同行中位数**，或者一张直观的 **历史估值区间带（PE Band）**。仅有一个百分比分位数，分析师根本无法直观判断当前是贵还是便宜。
2. **回报口径令人费解**：
   - 表格显示“事后财务归因（过去 12 个月）”和“驱动模型预期回报”，并打上黄色标签 `[ 简化估算 ]`。
   - 悬浮说明写着：*“采用了表下注明的假设：营业收入增长率持平、净利率持平、股数不变化……”*。
   - 分析师心声：如果收入持平、净利率持平、股数持平，这算什么“驱动模型”？这纯粹是静态平推！系统应该明确告诉分析师这是“基准平推情景”，而不是冠以复杂的量化名词。

#### 建议修改方案：
- 引入规范的 **多因子估值看板** 与 **历史走势图**；
- 明确标注预期回报的基准假设，并提供一键跳转至【情景与触发】页面进行动态敏感性测算。

### 4.5 子标签 ③：【风险与下一验证事件】(`risks`)

#### 存在问题：
1. **催化剂日历（Catalyst Calendar）缺乏重要性评级与时间轴排布**：

2. **“正在跟踪的验证条件”全是公式代码残片**：
   - 列表项显示：`基准情景：GenAI bookings quarterly run rate > $1B（季度披露值 >= 1000000000）`；

- 清除所有诸如 `>= 1000000000` 的公式代码，统一转换为规范中文：*“季度生成式 AI 订单额达 10.0 亿美元以上”*；
- 彻底修复 `causal_chain:0` 标签泄露，替换为具体的产业争议议题（如 *“议题一：生成式 AI 对传统 IT 咨询人员外包的替代速度”*）。

### 4.6 子标签 ④：【证据底稿与事实库】(`evidence`)

#### 存在问题：
1. **筛选器与信息架构极其繁重**：
   - 顶部提供“主题”与“来源类别”两个下拉菜单，外加一个“显示全部历史版本”切换开关；

2. **出处详情泄露数据库 ID**：

   - 这对于金融分析师毫无核查价值，分析师需要的是：**“SEC 10-K 第 48 页，Item 7 Management Discussion & Analysis，第 3 自然段”** 以及可以直接点击跳转查看该 PDF 对应页码的链接！
3. **分页与加载体验差**：
   - 底部是一个 `[ 加载更多 ]` 按钮，每次只加载 20 条，分析师想翻找较早前的纪要需要连续点击十几次，且页面越来越长无法快速回到顶部。

#### 建议修改方案：
- 剔除所有 `sha256:...` 内部寻址哈希；
- 改造为金融审计底稿（Working Papers）结构：按**年报/季报、电话会纪要、专家访谈、券商研报**四类资料来源分类呈现，每条结论附带精准的原文件出处链接与原文高亮对照。

### 4.7 子标签 ⑤：【财务模型与预测】(`model`)

#### 核心硬伤 Review：
这是整套 Cockpit 页面中**最为关键、却也是视觉与交互最糟糕**的子页面。
1. **文本框展示财务报表（`<pre class="v2-pre">`）的史诗级倒退**：
   - 财务分析师的核心生命线是三张表（损益表、资产负债表、现金流量表）。而当前系统直接用一段等宽文本框输出报表，既不能锁定行名，也不能左右平滑滚动，字体只有 12px，极易看错行。
2. **大面积的“缺失告警”掩盖了核心数据**：
   - 首屏赫然挂着折叠框：`12 项结果缺少计算条件（不能当作正式预测使用）`，列出“业务优化费用未提供预测值”、“少数股东损益缺少净利润基准”；
   - 甚至直接在行内把 JSON 打印出来：`{"concept":"us-gaap:..."}`；
   - 分析师看到满屏的“缺少计算条件”，对整份模型产生极大的不信任感。
3. **导出 Excel 模板绑定的交互反人类**：
   - 导出按钮旁边提供一个折叠框：`更改这家公司的默认模板`；
   - 分析师想给这家公司换一个中金或高盛格式的 Excel 模板导出，系统强制要求填写：`理由（必填，会和这次指定一起存档，例如：这家公司按 TMT 组的模板出模型）`；
   - 分析师只想导出一个表格，却被系统逼着填写审批理由！

#### 逐按钮审计与整改方案：

| 按钮/操作 | 当前行为 | 存在问题 | 重构方案 |
|:---|:---|:---|:---|
| `[ 导出财务模型（Excel） ]` | 点击后按钮 disabled，等待生成后直接通过浏览器下载 `.xlsx` | 无格式选项预览，若模型有缺项未告知导出的文件具体长什么样 | 提供导出浮层预览：支持选择**完整模型（含公式勾稽）**或**精简估值摘要表**，注明生成时间 |
| `[ 把所选模板设为默认 ]` | 需先在文本框填写理由，否则点击报错 focus 到文本框 | 纯属内部管理多余动作，导出文件无需强制写理由审批 | 彻底取消“填写理由”门禁，改为分析师下拉直接选择即可生效 |
| `[ 恢复按行业默认 ]` | 灰色幽灵按钮，混在表单底部 | 语义不清，用户不知道会恢复成什么样 | 明确提示：`恢复为系统内置标准三张表模板` |
| 报表等宽预格式化文本 | `<pre>` 标签渲染纯文本 | 无法选列、无法对齐、无千分符、无粘性表头 | **重构为现代化金融 DataGrid 表格组件**：支持固定首列科目、支持年报/季报切换、支持单元格悬浮查看预测假设与公式来源 |

### 4.8 子标签 ⑥：【事件研判】(`events`)

#### 存在问题：
1. **事件标题代码化泄露严重**：
   - 线上数据显示，部分新事件标题为 `sec:filing:0001688568-26-000068` 或 `calendar:earnings-release-intake:msft`；
   - 分析师无法从这种机器代码中看出究竟是发生了什么事件（是发布了 10-Q 季报，还是高管离职？还是重大诉讼？）。
2. **研判理由长篇大论、充斥套话**：
   - 每一条事件研判下方都附带长达两三百字的 `because` 文本，且往往多条事件的 `because` 完全一模一样（如连续 5 条都是“经核验该回购计划符合资本配置预期，维持现有观点不变”）；
   - 极度消耗分析师的阅读耐性。
3. **“事后复盘”模块概念混乱**：
   - 出现“我们当时以为：……”、“实际发生的：……”、“市场会怎样向我们靠拢：……”等口语化小标题；
   - 这种口语化标题翻译腔极重，完全脱离了机构投资备忘录严肃严谨的语境。

#### 建议修改方案：
- 严格清洗事件标题，统一格式化为：`[公告/财报/行业新闻] + 公司 + 核心事实摘要`（如：*“【季报披露】埃森哲发布 2026 财年 Q3 财报，营收同比增长 4.2%”*）；
- 合并相同结论的事件，提供简洁的观点变动指示：`● 盈利预测维持不变`、`▲ 目标价上调 +5%`；
- 规范事后复盘标题：改为标准金融术语 **【预期差分析】、【业绩偏离归因】、【逻辑修正与验证路径】**。

### 4.9 子标签 ⑦：【情景与触发】(`scenarios`)

#### 存在问题：
1. **情景概率调整的交互极度繁琐**：
   - 点击 `[ 调整情景概率 ]` 展开表单，表格列出乐观、基准、悲观三个情景的新概率输入框；
   - 当用户填写的三个概率加起来等于 95% 时，系统不仅报错，还生硬地算账：`保留的 3 个情景合计 95%（需要 100%，还差 5 个百分点）`；
   - 最致命的是：表单下方强制要求填写 `调整理由（必填，最多 600 字）`！如果理由留空，直接点击保存，系统弹红字错误拒不保存！
2. **缺乏即时的收益率/目标价联动测算**：
   - 分析师调整悲观从 20% 到 30%，最想看到的是**“加权目标价和期望回报率从 +15% 变成了多少？”**；
   - 当前系统完全没有联动实时计算，分析师在盲调数字，改完还要手写一篇理由。
3. **“停用这个情景”复选框语义危险**：
   - 表格最后一列为 `停用这个情景`。分析师一旦勾选，该情景直接被标记为 `retire` 并在后端注销。缺乏明确的二次确认与后果说明。

#### 建议修改方案：
- **引入金融级情景联动滑块（Scenario Slider）**：
  - 提供乐观/基准/悲观联动的交互滑块，拖动其中一个，另外两个可选择自动等比配平或手动锁定；
  - 实时在右侧联动展示：**加权期望目标价变化**、**加权期望 IRR / 收益率变动**；
- **取消强制必填调整理由**：将理由改为可选输入框（Optional Memo）；
- 保存按钮提供明确反馈：`[ 应用并重新测算目标价 ]`。

### 4.10 子标签 ⑧：【回报归因与利润桥】(`returns`)

#### 存在问题：
1. **多重口径混乱并置，分析师极易误读**：
   - 页面同时并列展示：
     - `事后财务归因（过去 12 个月）`
     - `驱动模型预期回报`
     - `一致预期回报`
     - `卖方目标价预期回报`
   - 上述四个口径的时间区间、计算基准、数据来源完全不同，系统却把它们的瀑布图和数据表一字排开，没有任何明显的分割对比视觉引导，分析师极容易将“事后财务走势”误以为是“对未来的预测”。
2. **“利润桥（Profit Bridge）”交互过于技术化**：
   - 利润桥用于展示从营业收入到净利润的各级扣减。但系统在柱状图下方展示了一长串勾稽检查代码：
     `[✓] 勾稽已通过，营业利润：差额 0 美元（缺：其他收益项目）`；
   - 柱子点击后，弹出的面板居然写着内部 XBRL 概念名称：`概念：us-gaap:OperatingIncomeLoss`。

#### 建议修改方案：
- 严格划清 **【历史走势归因（Past Trajectory）】** 与 **【未来收益预期（Future Expectation）】** 两大板块，界面上方提供醒目的 Tab 切换，严禁在同一视觉层级混排；
- 利润桥图表隐藏所有 `us-gaap:...` 机器标签，点击柱子展示清晰的财务会计明细卡片（如：`营业收入 $180.44亿 - 营业成本 $121.32亿 = 毛利润 $59.12亿`）。

### 4.11 子标签 ⑨：【研究报告与产物】(`reports`)

#### 存在问题：
1. **术语“产物”是标准的软件工程黑话**：
   - 代码中多处把研究产出称为 `产品` 或 `产物`（英文 `products` / `deliverables` 直译）。在投研团队中，这应该叫 **【投研报告】、【投资备忘录】、【深度研报】**。
2. **长篇大段未经审校的英文和占位符充斥报告正文**：
   - 点击 `[ 阅读 ]` 展开侧边阅读器，大量段落被替换为 `正文正在检查文字表达，完成后会显示。`；
   - 部分章节的来源列表赫然显示为：`已绑定来源 · 已绑定来源 · 已绑定来源`，长达数行完全重复，极其影响阅读。
3. **下载导出按钮单一且格式不符合机构习惯**：
   - 页面只有一个 `[ 下载研究报告 ]` 按钮，说明文字写着：`下载的是网页格式的完整研究报告（HTML）`。
   - 金融分析师向投资总监或投委会汇报，需要的是 **排版精美的 PDF 报告** 或 **可编辑的 Word 报告（.docx）**，给分析师一个 `.html` 文件是极度脱离现实投研工作流的体现。

#### 建议修改方案：
- 全面更名为 **【投研报告库】**；
- 彻底剔除无意义的重复“已绑定来源”字符串；
- 导出功能扩展支持：**标准排版 PDF 研报** 与 **Word 格式（.docx）**，并带标准机构级封面、免责声明与评级摘要。

### 4.12 【研究问答】页面 (`#/ask`)

#### 页面结构与交互审查：
- 顶部副标题：`每个问题单独回答，不会自动带上上一条问题的上下文；追问时请写清公司和期间。`
- 提问表单：研究对象下拉框 + 提问输入框 + 提问按钮；
- 提示文案：`回答只使用本项目已整理的资料，会产生一次 AI 调用费用，通常需要约一分钟。`
- 回答卡片：结论（3句话）+ 完整回答（折叠）+ 尚不能确认 + 主要依据（前5条展开，其余折叠）+ 底部费用与打标反馈栏。

#### 核心痛点与缺陷：
1. **机械刻板的“免责声明与费用警告”造成极差的第一印象**：
   - 用户还没打字，系统就先警告“不继承上下文”、“产生一次费用”、“等一分钟”。金融分析师面对的是高压快节奏的投研环境，这种提示充满了戒备心与机器冷酷感。
2. **缺乏多轮连续对话能力**：
   - 分析师提问：“万华化学过去四个季度的聚氨酯毛利率变化趋势如何？”
   - 得到回答后，分析师自然会追问：“那同期的纯 MDI 和聚合 MDI 价格走势呢？”
   - 现在的系统完全无法处理代词和上下文，分析师必须在历史记录中点击“基于这条追问”，然后在单行输入框中手动拼接长文本。这在 2026 年的技术背景下是不可接受的交互体验。
3. **回答内容被机械拆碎**：
   - 强制将回答截断为“结论（前3句）”和“完整回答（折叠）”。有时候第 3 句话根本没讲完（如被分号截断），导致结论生硬断裂，分析师必须每次都手动点开折叠看全文。

#### 逐按钮审计与整改方案：

| 按钮/操作 | 当前行为 | 存在问题 | 重构方案 |
|:---|:---|:---|:---|
| `[ 提问 ]` 提交按钮 | 发送 POST，开启轮询，等待 20~60 秒，无进度百分比 | 等待时间长，只有简单文字提示，分析师易焦虑 | 提供多阶段动态进度条（*“正在检索 10-K 底稿 → 正在提取财务数据 → 正在综合归纳”*） |
| `[ 基于这条追问 ]` | 把原问题加上前缀填充到输入框并滚动到顶部 | 根本没有实现多轮对话，只是复制粘贴文本 | **升级为原生对话流（Chat Thread）**，支持在当前会话中连续提问并保留多轮上下文记忆 |
| `[ 编辑后重问 ]` | 失败时带回原问题 | 体验尚可，但入口隐藏在折叠卡片内 | 当回答未达到预期或失败时，在回答卡片底部直接提供快捷建议与重试按钮 |
| 反馈按钮组（5个） | 点击记录“已阅读”、“有参考价值”、“证据不够”等 | 选项冗长且占用大幅版面 | 简化为标准的 **赞成（👍）/ 反对（👎）**，点击反对再弹出可选原因 |

### 4.13 【待我处理】审批与任务页面 (`#/tasks`)

#### 核心硬伤 Review：
这是系统体验最为恶劣、交互摩擦力达到顶峰的页面。
1. **“强制写理由”在待办中彻底泛滥**：
   - 打开页面，由于后台 6 个翻译批次失败，刷出了 6 张一模一样的卡片：`一批界面文字的中文翻译停下了：已连续失败 6 次，系统不会再自动重试`；
   - 分析师想清理这些无意义的卡片，点击 `[ 已知悉 ]` 或 `[ 暂不提醒 ]`，页面立刻弹出表单强制要求输入理由才能关闭！
   - 点击卡片上的 `[ 重新进行语言质检 ]`，弹出的表单同样强制要求写理由！
2. **“交由管理员处理”让分析师陷入绝境**：
   - 卡片上提供操作：`[ 复制给管理员的摘要 ]`。点击后把一段内部错误日志复制到剪贴板，提示：`已复制，请发给管理员：fetch-cap:public-web-url:sha256:...`。
   - 分析师心声：我是来用投研系统的，不是来给你们当系统故障工单中转员的！系统内部的接口超时为什么要我复制乱码去联系网管？！
3. **混淆了“投资决策”与“系统报错”**：
   - 真正的核心投资决策（如：*“埃森哲是否完成初步研报阶段，准予进入正式财务建模阶段？”*）被淹没在海量的“网页抓取失败”、“翻译超时”、“存储空间快满”等底层报警中。

#### 逐按钮审计与整改方案：

| 待办卡片类型 | 当前操作按钮 | 存在的问题 | 重构方案 |
|:---|:---|:---|:---|
| **研究阶段审批** | `[ 批准 ]` / `[ 拒绝 ]` / `[ 暂不处理 ]` | 决策依据折叠过深，分析师看不到核心财务指标就得盲点批准 | 卡片首屏直出核心依据看板（盈利预期、核心风险、置信度），一键批准；拒绝时提供快捷选项 |
| **语言质检失败** | `[ 重新进行语言质检 ]` + 强制理由 | 纯属内部 LLM 质检报错，根本不该展示给分析师 | **彻底移出分析师界面**，后台静默重试或降级显示英文，转交管理员日志 |
| **资料抓取受阻** | `[ 复制给管理员的摘要 ]` | 强迫分析师扮演运维，暴露 SHA256 哈希 | 转化为业务提示：*“暂无某公司最新纪要，已自动排队等待数据源更新”*，无需分析师介入 |
| **已知悉 / 暂不提醒** | `[ 已知悉 ]` + 强制理由 | 点击“知道了”居然还要写小作文 | **立即去除理由输入框，点击即刻消除卡片** |
| **专项研究停止** | `[ 停止这项专项研究 ]` + 危险红色 | 概念生硬，“停止车道”属于技术调度词汇 | 改为：`[ 暂缓跟踪该专项课题 ]`，提供常规弹窗确认 |

- **费用与系统配置剥离**：将复杂的 Token 计费池、管理员链接彻底收归到独立的 `/admin` 后台。

### 5.1 视觉与设计系统重构规范（Financial Design Tokens）

为了让系统真正具备专业金融终端的严谨、现代与可信度，必须建立针对金融场景的视觉规范：

