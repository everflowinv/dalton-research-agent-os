# Cockpit 中文文案建议逐项验收（2026-09-13）

## 验收边界

本表逐节核对《Dalton Cockpit 页面文字语言优化与“说人话”重构建议》。状态“代码已实现”只表示候选代码和离线测试通过；当前分支尚未部署，仍须以部署后的真实 DOM、五家公司数据和操作结果复验。原始记录、引用原文、财务概念代码、哈希和机器枚举不会被改写；需要时放入折叠的“技术详情”。

| 状态 | 含义 |

## 明确排除的建议

1. 不把 `unknown` 改成“待提审”。未知只说明系统无法确认，不能凭文案创造审批状态。
2. 不把所有 `BUDGET_REFUSED` 改成“单日预算耗尽”。只有证据明确包含日额度或预算池耗尽时才如此说明；否则显示“本次请求超出适用限制”。
3. 不宣称 Guidepoint、公司 Wiki、某数据源或某研究能力已上线。安装、mission 声明和 permission 是三个独立状态。
4. 不把系统生成的英文归纳冒充“原文引用”。规范化 citation statement 与其他系统正文均须走精确中文映射；命中时原始值只放技术详情。只有来源明确标记为逐字引文的字段才可在主体保留原文。
5. 不把当前资料不足、尚未运行或未获授权推断成投资结论、任务失败或人工否决。
6. 不将“投委会”等组织角色强加给实际仅要求 owner/human approval 的记录；界面使用“提交人工决策”。
7. 不采纳会凭空增加能力的句子：方向调整目前仅支持研究问题和目标，不能写成可调整数据源权重、任务调度或模型假设；结论库用真实分页，不宣称存在“导出全量事实库”按钮。
8. 不把不同模型供应商写成“强制不同技术架构”；网关状态不能推断为云端版本差异。模型身份和授权按真实记录显示。
9. 新闻来源不一概冠以“权威”，`other` 不固定解释成互联网；`Margin`、利润率或经营利润也不在缺少口径时擅自增加“毛利率”“EBIT”等含义。
10. 不照抄报告中的示例数字、年份和原因作为实时事实；新增资料不代表底稿已全部补齐，终止不等于内容核验失败，模型链失败不等于全部超时，尚无历史调整也不证明当前仍是初始方案。
11. 采用易懂、准确的表达，省去报告建议中“严谨问答声明”“绝不主观编造”“核心风控规则”等无助于操作的套话；高置信度也不附加未经验证的“证据链闭环充分”。


## 已确认待补

- **人民币式数量级显示**：统一数值 helper 已进入候选代码，本轮未改算法。候选测试覆盖金额、比例、EPS/ARPU 的显示规则；部署验收仍须用五家公司真实数据检查原始数值、换算单位与舍入一致。
- **真实 DOM 复验**：本候选只完成代码与离线快照验证；部署后仍需覆盖全部导航、五家公司详情、49 条审批展开、结论多页、Ask 及导出。
- **动态翻译字典覆盖率**：`ui-text-locations.json` 显示目标、问题、claims、events、planner 和历史文本均可能包含英文。必须用最终真实 Core 生成的精确映射检查未命中项；前端不会模糊翻译或猜测。
