# 公司研究推进修复记录

2026-10-11。范围为美国 IT 服务五家公司与 Hyperscaler 四家公司。农业覆盖草案保持待确认。

## 这轮解决什么

研究任务需要从“找到问题”继续走到阅读原文、核验数字、建立模型和形成报告。检查发现，若干任务停在这些环节之间：失败被当作仍在执行，完成的答案没有进入下一轮规划，完整分部口径被截断，模型超时被当作研究证据不足。

本轮按实际阻碍分批更新运行包。每批先用已有原文和模型回放，再检查部署后的正式产出。服务进程正常、任务成功执行和研究问题得到回答分别记录。

## 第一批代码

- 当前计划引用的历史原文可与最新版本同时读取，读取前重新核对原文与登记记录。
- 建模时可选择原文中的完整财务口径，由系统带入全部分部维度。同一申报期的收入分部和合并利润表一起保留。
- 已核验数字带着原值、单位、期间、定义及出处进入规划，供后续问题直接使用。
- 指定 SEC 申报的请求使用其实际申报日期。八份 Meta 请求中，七份在已有近期索引的离线回放中命中；较早的一份还需要历史归档路径。
- 季度增速敏感性分析把历史波动作用于首个预测季度，此后恢复原模型增速。比例假设仍覆盖整个预测期，正式预测保持原样。IBM 和 Meta 的真实模型各有二十个情景通过现有数值检查。
- 起草失败保留为执行问题，不生成研究缺口，不因此退回初筛。起草前先排除无法解析的引用，已成功起草的部分保存在运行记录中。
- 备忘录明确区分已回答的问题和待回答的问题。一次格式修复可以使用已核实结算所节省的额度，同时为后续各组及独立复核保留原有额度；总预算和最多一次修复的限制保持原设置。

## 各公司仍需观察的结果

| 公司 | 已确认的情况 | 后续验收 |
| --- | --- | --- |
| Amazon | 已有第二版十二季度正式预测；部分数字阅读失败被误报为进行中，初筛曾超时 | 阅读恢复并产生正式答案，报告继续起草 |
| Microsoft | RPO 总额及未来十二个月确认比例已有正式答案；报告起草中的超时曾导致退回初筛 | 规划复用答案，起草完成后再评估研究质量 |
| Meta | 指定申报日期未传入 SEC 查询；敏感性分析把单季高增速重复用于全部未来季度 | 获取实际原文及单位证明，发布当前模型对应的敏感性结果 |
| Google | 材料请求已找到资料，但收入历史与调节项尚未形成足够的可计算输入 | 将资料中的具体数字核验入库，全部历史期间核对通过后生成新预测 |
| IBM | 软件分部数据曾被输入长度限制排除，模型也漏抄分部维度 | 新模型使用完整口径；收入合计差异须找到真实调节项 |
| DXC | 原文完整，模型漏抄了其中一个分部维度 | 新模型使用完整口径并通过历史核对 |
| ACN | 已有第十一版预测，备忘录把同一问题同时标为未知并填写答案 | 起草和独立复核通过后形成新报告 |
| EPAM | 旧公式漏掉 2023 年第三季度的业务出售损失 2,592.2 万美元；另有数字阅读恢复的执行记录衔接错误 | 按各期真实披露组成核对全部历史；恢复任务产生有效答案 |
| CTSH | 部分业务驱动尚无对应的可计算数据，申报资料获取停在来源更新等待 | 取得具体驱动依据，或以有出处的可观察变量重新建模 |

截至本记录形成时，历史归档获取、Google 的数字入库衔接、EPAM 的逐期公式组成及部分执行恢复仍在继续修复。线上实际安装版本、服务检查和新增研究产出以[项目运行状态](../PROJECT_STATUS.md)及部署验收记录为准。
