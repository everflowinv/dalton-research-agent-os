# 按研究环节声明思考强度

技术设计与验收摘要，2026-10-10。隔离测试和历史回放用于核对合同与兼容性；不等同于当前公司研究已完成。原始研究材料、运行账单及逐文件收据私有留存。

通用 broker 控件显式传 `thinkingLevel`，允许 off/minimal/low/medium/high；无特别规则时为 low。初筛、投资备忘录、深度认知门与行业框架起草默认 medium。独立核验必须 low；Work、route、通用控件和 required provider controls 冲突时拒绝。

调整按用途追加有理由的路由政策版本，旧政策哈希不变。活动项目的配置同步逐一回执，失败项目不伪报成功。费用准入与正式结果记录请求强度；未记录的历史强度不回填。统计耗时是准入到结算，包含排队，未结算费用按预留额显示。

离线宿主最终 payload 复核确认请求值优先于模型固定参数，并暴露 DeepSeek descriptor 能力缺口；在 broker 专属路径补能力，不改交互 agent 的全局默认。muse 的 low 与 minimal 保持不同声明值，不用请求 low 冒充最终 native minimal。

Adapter 与 broker 闭合协议须一起发布。生产正式 Work/admission 的用途与思考强度可以精确关联；当前正式存储不保留原始 providerControlProof，因此 adapter 验证通过与原始供应商 payload 证据分开表述，不能从默认配置或成功状态推断最后一跳控件。

Python 路由、费用和 owner 同步专项，以及真实 Node UDS/HMAC 合成协议通过。H 的真实 low/medium 严格合同与独立核验已取得结果，但两档质量评分仍未通过；不据一次跨公司参考比较宣称 medium 普遍优于 low。
