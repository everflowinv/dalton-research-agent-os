# 开发基线收口与本批部署

2026-10-13。本批首先以 v0.11.45 收拢已完成修改并于 15:58 UTC 上线。后续全量 CI 发现后继任务尚未完成时旧原文未被保留的集成回归，统一修复纳入 v0.11.46，同时更新三组过时或受无关输出干扰的测试。main 合并等待最终必需检查通过，再建立大版本分支。线上验证见[v0.11.45 记录](runtime-v0.11.45-verification-2026-10-13.md)。

## 收拢范围

- 规划恢复动作互斥；财务附注选项交接到正式读取目标。
- 模型缺少精确申报科目绑定时，进入受限修正；历史资料不足形成明确依赖。
- 经营指标从原文列、单位和独立核验进入模型历史；动态输入规则与修正规则共用同一生成入口。
- 外国发行人 6-K 附件通过正常获取、原件核验和读取流程进入材料目录。附件取得不等于季度三表完成。
- 已有后继数字任务时，停止重复提出旧能力操作；研究未完成状态继续保留。
- 旧 Figure 期间文字碰撞产生明确冲突，已付结果可继续本地核验。期间不同仍为未解决，不自动合并；已付费用保持不变。

数字任务等待中或部分完成时，继续保留其绑定的精确原文版本；只有正式结果全部完成后才解除依赖。选择性读取继续检查文档身份及来源。

已保存的实现全部纳入本批。三个历史原型（早期单位身份、摘录尺度恢复、旧备忘录额度修复）已被后续实现替代，保留私有记录，不以旧代码覆盖当前实现。未完成的新能力记录在[架构问题报告](architecture-findings-and-major-version-2026-10-13.md)。

## 验证与发布

源包各自通过相关测试和独立复核；最终联合测试及 GitHub 必需检查以本批最终提交为准。仓库要求 Python 3.11、Python 3.13 与 OpenClaw broker 检查，通过正常 PR 合并。部署采用既有暂停派发、等待在途调用、备份、切换和恢复机制。

## 清理范围

上线确认后删除不再引用的旧构建和可重建的临时产物；只清理已结束、无服务引用且源码已保存的临时工作目录。研究数据库、原文、已付模型回答、费用账、当前运行包、回滚版本与未保存源码保留。进程逐项核对所属服务和任务，避免影响正在研究的环境。实际释放空间、清理路径和服务复查结果在执行后补记。
