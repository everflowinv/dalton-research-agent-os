## 一、 执行摘要与投研语言设计宪章

### 1.1 核心痛点诊断：为什么分析师会感到“困惑与畏手畏脚”？

Dalton Research OS 在最新版本中完成了由早期控制台向 Cockpit v2 工作台的架构演进，并引入了专门的中文文案替换表（`copy.js`）。然而，独立深入审查发现，系统中依然大量残存着**“系统开发者写给系统开发者看”**的痕迹，严重背离了专业金融分析师（买方/卖方研究员、投资经理、投研助理）的工作心智模型：

1. **底层工程架构概念严重外露**：页面上充斥着“规划器（Planner）”、“写入服务”、“流水线/车道”、“改绑票据”、“只读投影”、“模型网关/档位/链尾”、“SHA-256 哈希”、“token 上限”等研发词汇。分析师不是运维工程师，不需要也不应该被迫理解 Agent 的多进程协作调度机制。
2. **金融合规与投资歧义严重（甚至具备潜在诱导性）**：
   - 在任务卡片中将 API 重试写为**“再买一次”**——在投研场景中极易被误解为在交易终端“追加买入股票”，属于高危合规用词；
   - 出现“悲观情景概率”直接作为“综合风险”排名的现象，未说明潜在下行幅度；
   - 预期回报窗口写为“未来4个季度”，但实际基准日是数月前的历史季度，存在严重的时间错配。
3. **生硬的机械机翻与代码注水文字**：
   - 报表科目出现“本行为收入（Revenues）科目。”等代码直译注水句；
   - 情景触发条件直接显示为 `<`、`≥`、“此后研判为…的事件数”等程序布尔表达式，悬停甚至外露 `us-gaap:...`；
   - 事件与重要变化直接打印 `public-web-url:sha256:...` 或 `guidepoint-excerpt:...`，无法传达任何有效业务信息。
4. **交互施加过度心理负担与“算力恐慌”**：
   - 过去甚至连“已知悉”、“暂不提醒”都要弹窗强制填写“最多 600 字理由”，让分析师产生强烈的被系统审问感；
   - 提问与调整目标处处警告“产生一次 AI 费用”、“花一次起草费用”，把机构投研工具搞成了网吧计时器，极大抑制了分析师探索意愿。

### 1.2 金融分析师视角的四大文字设计原则

为了让系统真正成为机构级投研工作台，所有展现文字必须严格遵循以下四大原则：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        金融分析师投研语言设计宪章                             │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. 投资观点与核心分歧优先 (Theses & Variant Views First)                     │
│    - 首页与首屏聚焦：最新判断、预期回报、下行风险、核心分歧点。                     │
│    - 隐藏后台调度工单，只展现业务研究结论。                                    │
│                                                                             │
│ 2. 金融口径严谨透明 (Rigorous & Transparent Accounting Basis)               │
│    - 任何财务预测与估值倍数，必带：报告期 (FY/FQ)、基准日、GAAP/Non-GAAP 标记。  │
│    - 简化测算（如收入×历史净利率）必须在数字旁显式标注，绝不能混同为正式财务模型。 │
│                                                                             │
│ 3. 绝迹软件开发黑话 (Zero Engineering Jargon)                              │
│    - 彻底清除：票据、规划器、写入服务、车道、流水线、模型链、token、哈希等。       │
│    - 替换为：任务授权、投研系统、研究流程、课题、AI 辅助模型、数字指纹等。         │
│                                                                             │
│ 4. 低摩擦、非阻塞的极简操作闭环 (Low-Friction & Actionable Loops)            │
│    - 消除“强制写理由”；非破坏性操作（知悉、导出、重试）一键完成。                 │
│    - 消除零碎算力计费警示，费用统一收拢至设置页管理，不干扰日常提问与研判。        │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 二、 全局外壳与常驻组件文字评估与修改

全局外壳包括顶栏状态指示条、项目切换器、左侧主导航栏以及右侧常驻出处抽屉，是分析师每一次操作都会接触的核心界面。

### 2.1 顶栏状态指示条（Status Bar）

#### 现状审查与痛点
- 顶栏包括三大药丸状标签：服务状态、待办提示、页面刷新时间。
- 现状文案：
  - 药丸 1：`研究服务正常 · 最近一次进展 5 分钟前` / `研究服务暂停：新资料和结论暂不更新` / `研究服务状态暂时读不到` / `研究尚未开始：设定研究目标后开始`
  - 药丸 2：`待你处理 3 项` / `暂无待你处理的事项` / `待办暂时读不到（不代表没有待办）`
  - 药丸 3：`页面刷新于 10/09 12:00`
  - 按钮：`刷新研究数据`
- **问题分析**：
  1. “最近一次进展 5 分钟前”过于宽泛，分析师不知道是“行情更新”、“财报入库”还是“后台空转轮询（heartbeat）”；
  2. 药丸 3 写“页面刷新于”，但分析师容易误以为是“底层所有财报与股价数据都更新到了该时刻”（实际底层可能截至上一季度）。

#### 推荐修改方案

| 控件 / 位置 | 现有文字 | 推荐修改为 | 修改理由与金融场景说明 |
|:---|:---|:---|:---|
| 服务正常状态药丸 | `研究服务正常 · 最近一次进展 {time}` | `投研引擎在线 · 资料更新于 {time}` | “投研引擎”更契合机构软件定位；“资料更新于”准确表达是数据管道而非进程运转。 |
| 服务暂停状态药丸 | `研究服务暂停：新资料和结论暂不更新。请联系管理员恢复服务。` | `后台更新已暂停（已有研究可正常查看，新资料暂停录入）` | 明确区分“存量数据可用性”与“增量更新状态”，消除分析师以为系统全面崩溃的恐慌。 |
| 服务等待目标药丸 | `研究尚未开始：设定研究目标后开始` | `未设定研究目标（点击前往设定）` | 缩短文案，直接提供明确的行为预期与引导。 |
| 待办事项药丸 | `待你处理 {n} 项` | `待审阅与决策：{n} 项` | “待审阅与决策”突出买方投研权威（Sign-off/Review），而非廉价的工单打卡。 |
| 待办为零状态药丸 | `暂无待你处理的事项` | `决策事项已全部处理` | 肯定当前工作状态，给予分析师明确的心理结项反馈。 |
| 数据刷新时间药丸 | `页面刷新于 {time}` | `工作台界面同步于 {time}` | 明确是“界面视图同步时间”，避免误导分析师认为底层全部公司财报都截至该秒。 |
| 刷新按钮 | `刷新研究数据` | `同步最新数据` | “同步最新数据”更符合金融终端快捷刷新行情与模型状态的操作习惯。 |
| 数据变动提示条 | `有新内容` | `检测到底层研究数据更新，点击同步` | 更加明确业务含义，具备明确的可操作性。 |

### 2.2 项目切换器与左侧主导航栏

#### 现状审查与痛点
- 项目选择器标签为 `研究项目`，选项为项目名称（如 `美国云计算基础设施`）。
- 主导航栏 5 个主入口：`研究总览`、`公司研究`、`研究问答`、`待我处理`、`研究设置`。
- 导航折叠按钮：`收起导航` / `展开导航`。
- 底部常驻链接：部分版本底部仍保留“历史界面（旧版）”。

#### 推荐修改方案

| 控件 / 位置 | 现有文字 | 推荐修改为 | 修改理由与金融场景说明 |
|:---|:---|:---|:---|
| 顶栏项目下拉框 Label | `研究项目` | `当前研究组合 / 课题` | 分析师往往按“覆盖行业组合（Coverage Universe）”或“专题研究（Sector Theme）”管理项目。 |
| 项目切换辅助提示 | `切换后打开所选项目的研究总览` | `切换研究覆盖组合` | 更加简明。 |
| 主导航 Tab 1 | `研究总览` | `研究总览` (保留) | 结构清晰，与金融分析师 Dashboard 认知一致。 |
| 主导航 Tab 2 | `公司研究` | `覆盖公司` 或 `公司研究` (保留) | “覆盖公司”更符合卖方/买方 Coverage 术语，若保留“公司研究”亦可。 |
| 主导航 Tab 3 | `研究问答` | `智能投研问答` | 提升专业感，明确基于公司知识底座的即时问答定位。 |
| 主导航 Tab 4 | `待我处理` | `待办决策` | “待办决策”明确该页面聚合的是“模型发布审批”、“情景确认”、“假设审核”等核心决策。 |
| 主导航 Tab 5 | `研究设置` | `投研规则与设置` | 突出不仅是系统参数，更包含“投资评级门槛”、“情景规则”、“覆盖名单”等投研纪律。 |
| 导航栏底部旧版入口 | `返回旧版` / `历史界面（旧版）` | 从主导航中移除，移入 `投研规则与设置 → 帮助` | 严防两套截然不同的交互模型混淆用户心智；正式工作台绝不常驻旧版入口。 |

### 2.3 右侧常驻抽屉（出处/全文/历史）

#### 现状审查与痛点
- 点击“查看原文与出处”或报表对账时，从右侧滑出抽屉。
- 抽屉标题：`来源与原文`、`关闭面板`。
- 抽屉正文：当底层缺少原件时，显示英文 statement 或显示 `原文段落暂不可用：存档里没有这段原文`。
- 底部显示：`技术标识`（展开为 `claim_ref`, `identity_hash`, `source_ref`）。

#### 推荐修改方案

| 控件 / 位置 | 现有文字 | 推荐修改为 | 修改理由与金融场景说明 |
|:---|:---|:---|:---|
| 抽屉顶栏主标题 | `来源与原文` | `事实底稿与引用出处` | 金融审计底稿（Working Papers / Source Filing）概念，突出可信与可穿透核查。 |
| 抽屉关闭按钮 | `关闭面板` | `关闭 [Esc]` | 提示键盘快捷键，符合金融分析师快速操作习惯。 |
| 无原文时的警示卡 | `原文暂不可用：这条结论的出处没有可以打开的原文或存档段落，下面是它的登记记录。` | `未关联原始文件全文（仅保留系统摘录记录，请谨慎作为核心投资依据）` | 站在分析师合规防风险立场，明确警告“此记录未穿透至正式申报文件，不可盲信”。 |
| 原文阅读按钮 | `阅读存档全文` | `查看申报文件原件 / 纪要全文` | 明示文件类型（SEC 10-K/Q 申报文件或专家纪要原件），而非模糊的“存档”。 |
| 外链按钮 | `打开原文 ↗` | `在 SEC EDGAR / 来源平台查看 ↗` | 准确标注外部去向（如 SEC 官方或来源系统），增加专业透明度。 |
| 底层折叠区 | `技术标识` | `数据版本与溯源指纹` | 替代程序员术语“技术标识”，向合规审计语言靠拢。 |

## 三、 一级页面 ①：研究总览 (`#/overview`) 文字评估与修改

研究总览是分析师每天打开系统的第一屏，承担着“30 秒内获知最新核心研判、异动原因、影响公司及下一步行动”的使命。

### 3.1 核心四问首屏概览（Hero Section）

#### 现状审查与痛点
- 现状：首屏展示大字 KV：`最新判断`、`变化原因`、`影响公司`、`下一步`。
- 问题：
  - 当无观点变化时，经常机械拼接：`ACN · Accenture：当前观点不变（2026-10-09）`；
  - 原因栏经常出现：`近期没有改变观点的新证据；最近一次研究（ACN · Accenture，2026-10-09）维持观点：维持现状。`（“维持观点：维持现状”出现荒谬的复读机语义）；
  - “下一步”如果出现待办，直接机械套用内部任务名：`controlled_recovery:lane:...（待我处理共 7 项）`。

#### 推荐修改方案

| 模块 / 字段 | 现状典型文字 | 推荐修改为 | 修改理由与金融场景说明 |
|:---|:---|:---|:---|
| 首屏标题 | `研究总览` | `研究总览 · 投研动态看板` | 强化 Dashboard 定位。 |
| 空白项目引导标题 | `这个研究项目还没有研究目标` | `当前研究组合尚未设定研究目标` | 消除口语化“这个项目还没有”，规范为专业书面语。 |

| 出现待办时的字段 4 | `放行一次重新进入（待我处理共 7 项）` | `待审阅研究事项：共 7 项重点决策待确认（首要：Accenture 2026Q3 业绩复盘）` | 提取首要业务事项，给出明确的业务上下文。 |

### 3.2 行业论点与观点演变

#### 现状审查与痛点
- 现状包括两部分：`行业论点`、`公司论点`，以及折叠的 `观点演变（N 条旧版本，非当前）`。
- 历史痛点：曾发生同一页面“需求正接近底部”与“底部仍未确认”两个相互对立的论点并排展示，让分析师根本不知道系统到底看多还是看空。
- 目前改进后虽将旧版本折叠，但标签标注为 `非当前`、`已被修订取代`。

#### 推荐修改方案

| 控件 / 位置 | 现有文字 | 推荐修改为 | 修改理由与金融场景说明 |
|:---|:---|:---|:---|
| 板块标题 | `行业论点` | `行业核心观点与宏观假设（当前生效）` | 强调这是当前的“宏观/行业基准假设”。 |
| 置信度标签 | `置信度：高` / `中` / `低` | `证据充分度：高` / `中` / `低（资料尚存缺口）` | “置信度（Confidence）”在统计学易混淆，金融分析师更关注支撑逻辑的证据充分程度。 |
| 版本与生效时间 | `截至 2026年10月09日 · 第 3 版 · 观点维持` | `生效基准日：2026-10-09 · 研判版本：v3 · 本次跟踪：维持基准假设` | 规范日期与版本表达。 |

| 旧版本注释说明 | `旧版本已被后来的版本修订取代，只供对照观点怎么变化；当前结论只看上面的论点。` | `本区域记录随宏观环境与业绩期推移而修正的历史研判，用于复盘研判逻辑演进；当前决策请以上方生效观点为准。` | 阐明保留历史版本的投研复盘价值。 |

### 3.3 各公司当前判断与重要变化

#### 现状审查与痛点
- 各公司判断卡片：显示公司名、`核心情景：...` 或 `暂无投资观点：现有资料还不足以形成判断`。
- 重要变化区域：按时间倒序混杂展示“观点调整”、“股价异动”、“新增资料”。
- 痛点：
  1. 经常出现 `新增资料 · guidepoint-excerpt:sha256:7b8e...`，完全看不出是什么专家访谈；
  2. 股价变化直接显示 `近 5 个交易日 +5.2%`，却未说明是否创下新高或跌破关键均线；
  3. 证伪预警显示 `证伪预警触发：1 个情景已失效`，语气生硬，缺少对投资回报影响的说明。

#### 推荐修改方案

| 模块 / 字段 | 现状典型文字 | 推荐修改为 | 修改理由与金融场景说明 |
|:---|:---|:---|:---|
| 公司卡片无观点状态 | `暂无投资观点：现有资料还不足以形成判断` | `尚未建立正式投资观点（正在搜集公司报表与研报资料）` | 说明原因与正在进行的动作，消除死胡同感。 |
| 公司卡片判断理由摘要 | `理由` (折叠) | `查看论证逻辑与核心假设` | 提升信息专业度。 |
| 重要变化板块标题 | `重要变化` | `近期重大异动与增量信息` | 区分“重大异动（观点/股价）”与“日常入库资料”。 |
| 资料类事件（哈希标题） | `guidepoint-excerpt:sha256:... 新事件，内容待整理` | `新增专家访谈纪要：北美 IT 服务外包景气度交流（内容解析中）` | 严禁外露 SHA-256，展示解析后的话题标题。 |

## 四、 一级页面 ②：公司研究 (`#/companies`) 与公司主壳层

### 4.1 覆盖公司全景比较矩阵（列表页）

#### 现状审查与痛点
- 搜索栏提示：`查找公司：输入公司名或代码`。
- 表格列展示：`公司`、`当前观点`、`预期回报`、`估值倍数`、`风险：悲观情景概率`、`下一催化剂`、`待我处理`。
- 痛点：
  - “风险：悲观情景概率”极为荒谬。例如概率 25%，分析师一眼看去以为这是风险评分（Risk Score），完全不知道这是指下行概率，更不知道下行幅度是跌 10% 还是跌 50%；
  - 排序时，出现“不可比较”直接占满半张表格，文字只写“不可比较”，未在第一层提示究竟是期间不一致还是模型缺失。

#### 推荐修改方案

| 表头 / 控件 | 现有文字 | 推荐修改为 | 修改理由与金融场景说明 |
|:---|:---|:---|:---|
| 搜索框 Label 与 Help | `查找公司：输入公司名或代码` | `筛选覆盖标的：输入公司简称、全称或美股代码（Ticker）` | 贴近美股研究习惯。 |
| 表头列 1 | `公司` | `标的名称 / 代码 (Ticker)` | 明确标示 Ticker 字段。 |
| 表头列 2 | `当前观点` | `投资观点与评级状态` | 涵盖观点（多/空/中性）与研究成熟度。 |
| 表头列 3 | `预期回报` | `12M 预期回报率（年化）` | 必须强制带上时间窗口（12个月）与度量方式。 |
| 表头列 4 | `估值倍数` | `关键估值倍数 (P/E / EV/EBITDA)` | 标出代表性的主流倍数。 |
| 表头列 5 (致命缺陷) | `风险：悲观情景概率` | `下行风险情景（发生概率 / 潜在跌幅）` | **彻底消除伪风险评分**：明确这是“悲观情景”，并列出概率与潜在跌幅。 |
| 表头列 6 | `下一催化剂` | `下一催化事件与日期` | 明确包含 Event 和 Date。 |
| 表头列 7 | `待我处理` | `待办决策` | 与全局导航统一。 |
| 单元格不可比状态 | `不可比较` | `口径暂不可比（预测周期不一致）` | 一句话解释为什么不能排在一起，不用分析师再点开查看。 |
| 单元格缺失模型状态 | `无法计算` / `—` | `模型预测待完善` | 说明是处于生成中或数据缺失，而非算法崩溃。 |

## 五、 公司详情九大子章节文字逐项评估与修改

### 5.1 章节 1：投资观点 (`view`)

#### 现状审查与痛点
- 现状文字：
  - `当前观点以基准情景为准：...`
  - `最近一次研究判断：2026年10月09日 · 暂无投资观点，本次资料未足以形成新判断`（既然前面以基准情景为准，这里又写暂无投资观点，前后逻辑自相矛盾！）；
  - `报告摘要：初步研究筛查报告（2026年09月14日，历史报告，不是当前观点）`；
  - 关键数字卡片出现：`adjusted EPS growth（第一季度）：10 个基点（变化量）`，未标注财年，单位混淆。

#### 推荐修改方案

| 模块 / 字段 | 现状文字 | 推荐修改为 | 修改理由与金融场景说明 |
|:---|:---|:---|:---|
| 核心观点引导语 | `当前观点以基准情景为准：{name}` | `基准投资论点 (Base Case Thesis)：{name}` | 标准投资分析表述。 |
| 前后自相矛盾的研判记录 | `最近一次研究判断：... · 暂无投资观点，本次资料未足以形成新判断` | `最新研判动态（2026-10-09）：增量资讯已核验，本期资料未触发基准论点调整，维持原评级` | 彻底消除“有观点”和“无观点”在同一屏幕上的逻辑打架。 |
| 历史报告摘要折叠标题 | `报告摘要：初步研究筛查报告（...，历史报告，不是当前观点）` | `历史底稿参考：初步研究立项报告（2026-09-14 初稿摘要，最新数据请见上文）` | 明确这是“立项初稿”，避免分析师将其当成落后的失效观点。 |
| 历史报告阅读按钮 | `阅读初步研究筛查报告全文` | `阅读立项报告原件` | 简洁清晰。 |
| 关联行业论点小标题 | `相关行业论点（当前）` | `驱动本标的的宏观与行业前提（生效中）` | 明确行业论点对公司具体标的的上下游传导作用。 |
| 关键指标卡片：行名 | `adjusted EPS growth` | `调整后摊薄每股收益增速 (Non-GAAP EPS YoY)` | 补齐 Non-GAAP 与 YoY 同比定义。 |
| 关键指标卡片：期间 | `第一季度` | `FY2026 Q1（2026财年第一季度）` | 必须标清公司所属财政年度（Fiscal Year）。 |
| 关键指标卡片：数值 | `10 个基点（变化量）` | `+10 bps (同比增长 0.10 个百分点)` | 规范基点缩写（bps），消除“变化量”歧义。 |
| 财务模型概况标签 | `财务模型：尚未建立` | `预测底稿：三大表盈利预测编制中` | 消除冷冰冰的“尚未建立”，告知当前投研工作进度。 |

### 5.2 章节 2：估值与回报 (`valuation`)

#### 现状审查与痛点
- 估值指标表格：
  - 表格标题：`估值指标，按 2026年10月08日 收盘价计算`；
  - 说明列：当不可用时，偶尔仍冒出英文或生硬解释：`缺少计算所需的申报数据，暂不能计算`；
  - 历史分位表头：`历史分位 ?`（带问号按钮）。
- 回报对照表：
  - 出现“简化估算”标签；
  - 列名：`回报类型`、`期间`、`总回报`、`股价回报`、`目标价`；
  - 第一行：`已实现：过去 12 个月（事后财务归因）`；
  - 第二行：`模型预期（未来 4 个季度）`，但窗口却是 `2026/06/01 至 2027/05/31`，而当前已经是 2026 年 10 月，部分季度其实已经过完！

#### 推荐修改方案

| 模块 / 字段 | 现状文字 | 推荐修改为 | 修改理由与金融场景说明 |
|:---|:---|:---|:---|
| 估值表标题 | `估值指标，按 {date} 收盘价计算` | `当前主要估值乘数（基于 {date} 美东收盘行情）` | 规范金融学术语（Valuation Multiples）。 |
| 估值表说明列：缺失原因 | `缺少计算所需的申报数据，暂不能计算` | `待补充近四个季度利息支出及总债务数据` | 准确提示缺哪项会计科目，便于分析师补录。 |
| 历史分位说明 | `过去 250 个交易日样本` | `近 1 年交易日历史分位 (Percentile, N=250)` | 国际通行的量化统计口径说明。 |
| 回报表标题与说明 | `回报：实际与预期 · 实际回报与各类预期分开列示；预测的限制写在数字旁边。` | `预期总回报空间与多口径测算对照 (Expected Total Returns)` | 明确这是“预期回报测算对照”。 |
| 历史事后归因行名称 | `已实现：过去 12 个月（事后财务归因）` | `历史已实现总回报 (过去 12 个月 TTM 业绩驱动归因)` | 强化 TTM 历史已实现属性。 |
| 预测窗口错位警告 (重要修复) | `模型预测期：... 部分期间已结束` | `模型预测周期：FY2026 Q4 - FY2027 Q3（基准预测生成于 6 月，部分历史期需滚仓更新）` | **防止重大决策失误**：明确告知分析师模型基准点发生漂移，需要重新滚仓（Roll-over）。 |
| 简化估算角标文字 | `简化估算：基于收入的简化测算` | `粗算估算 (Simplified Projection)：仅基于营收复合增速×历史稳态净利率，未完成三大表资产负债表配平` | 严肃告知分析师这是顶层粗算，严禁作为严谨 DCF 结果使用。 |
| 目标价表头 | `目标价` | `12 个月基准目标价 (12M Target Price)` | 标明目标价期限。 |

### 5.3 章节 3：风险与下一验证事件 (`risks`)

#### 现状审查与痛点
- 现状内容：`下一验证事件`、`正在跟踪的验证条件`、`主要风险（悲观情景）`、`核心争议`、`资料清单`。
- 痛点：
  1. 下一事件经常选一个除息日（Dividend Ex-date），却没有任何关于“它对核心投资逻辑有何验证意义”的说明；
  2. 验证条件直接出现程序员逻辑表达式：`Revenues_growth < 3% · （截至6月30日，此后研判为…的事件数 ≥ 1）`；
  3. 悲观情景概率只说 `概率 25%`，叙述文字截断为 240 字灰字。

#### 推荐修改方案

| 模块 / 字段 | 现状文字 | 推荐修改为 | 修改理由与金融场景说明 |
|:---|:---|:---|:---|
| 催化剂日历小标题 | `下一验证事件` | `下一关键催化事件 (Upcoming Catalyst & Verification)` | 强化催化与验证双重属性。 |
| 业绩公布事件标签 | `FY2026 Q3 业绩发布：2026年12月18日（70 天后）· 日期未确认` | `2026 财年第三季度财报公布（预计 2026-12-18，距今 70 天，上市公司尚未正式定档）` | 用中文完整表达未定档状态。 |
| 逻辑验证指引 | 无说明 | `关键观测点：重点检验 GenAI 订单转化率与咨询部门订单收入比 (Book-to-Bill)` | 明确告诉分析师看财报时要盯紧哪个关键指标。 |
| 跟踪条件表达式 (消除代码) | `Revenues < 3% · （rule: growth < 0.03）` | `预警触发线：营业收入同比增速放缓至 3.0% 以下` | **彻底废除程序规则表达式**，翻译为专业投研指标线。 |
| 悲观情景标题 | `主要风险（悲观情景）` | `下行风险敞口（悲观情景推演）` | 投研下行保护意识。 |
| 悲观情景概率与测算 | `概率 25% · narrative...` | `发生概率：25% ｜ 潜在估值折价：−22.4% ｜ 预期目标价：$245.00` | 必须同步给出潜在回撤幅度。 |
| 核心争议议题标题 | `核心争议` | `多空核心分歧议题 (Variant Perception & Key Debates)` | 买方投研最看重的 Variant Perception 概念。 |
| 争议阅读按钮 | `阅读核心争议全文` | `查看多空深度分歧与论据对撞全文 →` | 激发分析师阅读多空对比论证的兴趣。 |

### 5.5 章节 5：财务模型与预测 (`model`) 及 Excel 导出

#### 现状审查与痛点
- 现状：顶部为可用性摘要，中间为财务网格（表格），底部为 Excel 导出面板。
- 痛点：

  2. 当底层模型缺失时，曾直接显示 `<pre>Revenues: 18044066000 ...</pre>`，无千分位，无表头冻结；
  3. Excel 导出面板在缺少预测时，仍显示导出按钮，且说明文案甚至写 `导出的文件包含当前版本的全部预测`（实际导出的 Excel 里全是空表格！具有严重误导性）；
  4. 更改模板时弹出“理由（可选）”，提示“可以不填；不填时记录为在公司页把导出模板改为...”，十分啰嗦。

#### 推荐修改方案

| 模块 / 控件 | 现有文字 | 推荐修改为 | 修改理由与金融场景说明 |
|:---|:---|:---|:---|
| 模型完备度摘要 (卡片顶部) | `可用：营业收入、营业利润；尚未完成：净利润、每股收益` | `三大表预测完备度：营收与营业利润预测已就绪 ｜ 净利润、稀释 EPS 及资本开支测算待补齐` | 明确指出哪项核心盈利指标尚未封闭。 |
| 模型版本与生成时间 | `第 2 版 · 预测生成于 2026年09月30日 · 包含全部主要科目 · 季度` | `财务模型基准版本：v2.0 ｜ 预测生成基准日：2026-09-30 ｜ 预测颗粒度：按季度 (Quarterly)` | 国际金融标准格式。 |
| 模型未完成提示折叠区 | `12 项结果没有算出（不能当作正式预测使用）` | `待封闭预测科目及阻断原因（共 12 项，暂未计入正式财务底稿）` | 严谨合规口径。 |

| 模板选择下拉框 Label | `导出模板` | `财务模型套用模板风格` | 贴合基金常用模板习惯。 |
| 更改默认模板折叠区 | `更改这家公司的默认模板` | `为该标的配置专用基金 Excel 模板` | 突出专业定制属性。 |

### 5.6 章节 6：事件与研判 (`events`) 及初步业绩对账

### 5.7 章节 7：情景与触发 (`scenarios`) 及概率调整表单

#### 现状审查与痛点
- 现状：情景对照表格（乐观/基准/悲观），表格上方显示：`情景对照：概率合计 100%；情景假设，暂未估值（没有目标价或回报区间，不能算加权期望回报）`。
- 点击“调整情景概率”展开内联表单：
  - 滑杆与数字框联动；
  - 差额平衡按钮：`把差额放到基准情景`；
  - 保存按钮：`整组保存`；

| 控件 / 位置 | 现有文字 | 推荐修改为 | 修改理由与金融场景说明 |
|:---|:---|:---|:---|
| 表格说明文字 | `情景对照：概率合计 100%；情景假设，暂未估值（没有目标价或回报区间，不能算加权期望回报）` | `多情景推演对照表 ｜ 当前情景概率合计 100% ｜ 各情景估值模型未完全闭环，暂不展示概率加权目标价` | 语言更加平实专业，说明未闭环原因。 |
| 情景表头列 1 | `情景` | `宏观与经营情景 (Scenario)` | 标明是 Scenario。 |
| 情景表头列 2 | `概率` | `主观概率权重 (Weight %)` | 强调是加权用的概率。 |
| 情景表头列 3 | `关键假设` | `核心经营假设与外部宏观环境` | 丰富内容属性。 |

### 5.8 章节 8：回报归因与利润桥 (`returns`)

#### 现状审查与痛点
- 现状：展示事后财务归因与各类预期回报归因，下方嵌有利润桥瀑布图。

#### 推荐修改方案

| 模块 / 字段 | 现有文字 | 推荐修改为 | 修改理由与金融场景说明 |

| 归因板块副标题 | `总回报 +14.2%，单位：百分点` | `过去 12 个月股价总回报归因分析 (Total Shareholder Return Attribution)` | 国际通行的 TSR 归因标准。 |

| 杜邦利润桥图表标题 | `基本面利润桥` | `经调营业利润同比变动桥接分析 (Operating Profit Bridge Waterfall)` | 标准 Waterfall 标题。 |
| 瀑布图单位标注 | 柱子末尾反复打印 `+2.4 个百分点` | 表头统一定义 `单位：基点 (bps) 或 百分点 (pp)`，柱顶仅保留带符号数值如 `+240 bps` 或 `+2.4 pp` | **大幅消除视觉噪点**，符合华尔街投行研报 Charts 习惯。 |

## 七、 一级页面 ④：待我处理与决策审批 (`#/tasks`) 文字评估与修改

待我处理中心汇集了系统请求人工把关的全部决策。它是系统与分析师交接研究控制权的核心纽带。

### 7.1 分组标签与优先级体系

#### 现状审查与痛点
- 现状分为 4 组：
  - `研究决定`
  - `资料与报告`

  2. “需管理员处理”让分析师不知道自己该干什么，容易以为系统处于不可用状态。

#### 推荐修改方案

### 9.2 财务单位、货币与千分位规范

在财务报表、倍数与行情展示中，严格杜绝开发常见的格式问题：
1. **统一金额单位**：表头必须统一标明 `金额单位：百万美元 (USD in Millions)` 或 `金额单位：亿美元 (USD in Billions)`；严禁单元格内忽而写 `18044066000`，忽而写 `$18.04B`；
2. **强制千分位与小数位**：所有绝对金额与股数强制三位千分位分隔符（如 `18,044.1`），常规金额与比率保留两位小数，基点保留整数或一位小数；
3. **涨跌颜色严禁反转**：遵循国际通用金融终端惯例（美股市场：绿色上涨、红色下跌；若支持国内习惯需提供一键切换，绝不能在同一页面红绿混用）。
