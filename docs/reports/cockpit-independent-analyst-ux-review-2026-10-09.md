# Dalton Research OS Cockpit：面向金融分析师的独立完整审查

审查日期：2026-10-09（纽约时间）。审查者：本会话独立审查 agent。源码基线：`e975673a148535980d7e3fc07e715c98a5dbcc9d`。本报告独立取证、独立判断，未阅读或合并其他 agent 的审查结论，也未修改产品代码。

## 1. 结论

新版已经有合理的五个主入口，财务图表也开始区分已披露、推导和预测。但它仍然要求分析师理解后台机制、自己判断状态是否矛盾，并在多个页面之间拼出一个完整答案。当前最需要修复的不是配色，而是信息可信度、内容优先级和操作闭环。

最严重的三项是：**同一公司的回报在不同表格里采用不同的比较规则；“原文与出处”无法真正打开原文；相反的行业观点都被当成当前研究结论展示。** 随后应解决内部编号和技术用语外露、追问没有上下文、需要人工判断却没有入口、写操作成功后页面不更新等问题。

目标体验应当是：分析师打开后，30 秒内知道“最新判断、变化的原因、影响哪家公司、下一步要做什么”；必要操作可在当前对象上完成；无需认识 hash、writer、车道、规划器、模型路由或命令行。金融术语如 EPS、GAAP、估值倍数可以保留，但需口径准确，不能用删减必要金融信息来换取简洁。

环境：8793 美国 IT 服务（ACN、CTSH、EPAM、IBM、DXC）；8795 大科技（AMZN、GOOGL、META、MSFT）；8794 空白项目。浏览器视觉观察为约 1200×930 的 Chrome 窗口、浅色主题。深色、手机、缩放和完整辅助技术测试未实测，仅检查相关实现并列出验收要求。

本次通过本机研究服务的只读读取方式取证，并使用只允许 GET、拒绝 POST 的本机审查代理打开页面。未改变认证配置、未开放公网、未提交研究/审批/预算/发送操作。项目会持续更新，另一个 agent 也可能操作：例如本次先见 7 项待办，稍后见 3 项；不能把这类变化直接判断为计数缺陷。

**B** = 浏览器现场确认；**S** = 源码确认实现或条件分支；**D** = 实际接口数据支持；**H** = 尚待交互复现的风险。表中不会把 S/H 当作成功执行过写操作的证据。

严重度：P0 为容易让用户据错误信息形成研究判断、或关键核实入口名实不符；P1 为主要任务难以完成/容易误操作；P2 为效率、文案或视觉问题。它们是本次产品审查分级，不表示已经发生交易损失。

## 12. 每个按钮的审查口径和动作台账

按钮不是只检查能否被点，还检查名称是否准确、对象是否明确、输入是否可理解、执行前是否知道影响、执行中能否离开、完成后状态是否更新、失败是否能恢复。重复渲染的同类按钮按组件归组；例如20条证据的来源按钮采用同一实现，不能把它们计成20个独立问题。

## 13. 文案修改样例

下列是推荐表达，不改变保存的原始研究内容；所有改写必须保留金融事实、方向、单位、时间和不确定性。

| 现有表达 | 推荐表达 |
|---|---|
| 放行一次重新进入（不花钱） | 重试这项研究。说明：恢复操作本身免费，继续分析仍使用项目预算。 |
| 撤回这项研究（规划器可按当前预算重新立项） | 停止这项研究。说明：已有成果保留，需要时可重新开始。 |
| 按钮通过写入服务以你的身份执行… | 操作会记录在项目历史中。 |
| 有一整个环节停着 / 挡住了整条研究链 | 专项研究暂停 / 项目尚未开始。 |
| 核心情景：订单温和、AI兑现偏慢 | 当前判断：订单增长平稳，AI新增收入仍待验证。 |
| 可选咨询 / 可支配咨询 / 非刚性咨询 | 客户可推迟的咨询项目（按业务原意选一种统一表达）。 |
| 最终留存的交付节省 | 提效带来的成本节省，最终有多少能留在利润中。 |
| 滑单陆续成交 | 延迟签约的订单陆续落地。 |
| market/provider/ref/hash/derived | 业务状态和可读来源名；derived依具体含义译“推导数据/转述”，不机械统一。 |
| 这一条由你判断，程序不读 | 等待你确认：这项条件是否已发生？ |
| 查看原文与出处（实际无原文） | 查看结论记录；取得真实原文后再用“查看原文”。 |
| 每次AI调用、票据改绑、路由、回执 | 一次分析 / 后台配置变化 / 当前处理结果；技术细节留管理员。 |

| 多空地图 / 核心争议 / debate_map | 核心争议；分“支持观点/反对观点/待验证”。 |
| 目的地（可选） | 发送到；默认“只在工作台保存”，其他选已连接群组。 |

写作规则：每张卡默认一句结论、一句依据、一句下一步；用户无需先读教程才能点按钮。少用“会由原writer…/不会修改authority…”解释权限，多用“确认后生效/已有成果保留/费用不超过…”。避免所有内容都“已核实”“已通过”：说清楚核实了什么，仍缺什么。英文原文可保留在来源阅读，不应作为未翻译系统状态流入主界面。

## 14. 建议的信息结构与设计方案

**研究总览**：一句当前观点；近7日三项重要变化；最多三项优先决定；一张统一公司比较表。研究记录在次级入口。

**公司研究**：顶部固定“观点、预期回报及口径、主要风险、下一验证、资料成熟度、最后变化”。正文分“观点与证据 / 财务与估值 / 情景与事件 / 研究报告”，九章节目录可作为详细导航，避免九个独立的大卡同时铺满。

**问答**：公司/期间上下文可见，支持真实追问；回答结构为三点摘要、论证、尚不能确认、可打开来源；历史结果可检索。

**待我处理**：一件业务事项一张卡，“发生了什么、影响什么、建议做什么”，主操作一个、次操作最多两个。维护事项默认折叠/转管理员，消息已知悉与真正审批分开。

**设置**：范围、费用、投资规则、模板、简报各有二级页。平时只读当前值，点修改再展开。管理员六区保持，但禁止分析师为了选模板/增公司而进入模型链或命令区。

视觉：正文14–16px，金融数值对齐并使用等宽数字；卡片标题16–18px，页面标题24–28px；将大量18px圆角嵌套卡减少到一个层级；主按钮稳定实色，危险动作用清楚标题和文案而不是单靠红色。图表保留实虚线与数据表，减少重复标题和元数据。缺失与零必须区分；风险提示靠近数值；颜色使用“增加/减少”和正负号说明，不假设所有金融分析师都遵循同一红绿市场习惯。

保留已有良好能力：独立公司URL、浏览器返回、未保存输入按项目隔离、正文/图表分历史与预测、可访问数据表、准确的上下文超限说明、决定状态回查。不要在重构中失去这些能力。

## 15. 修改顺序与完成验收

### 第一批：正确性与可核实（P0 + 关键P1）

1. 统一回报比较、窗口和排序，合并双表（O01/O13）。
2. 当前论点去历史重复并清楚呈现真实分歧（O02）。
3. 建立原始证据跳转链，修正“原文”按钮（C10/C13/A03）。
4. 所有业务页禁止显示内部ID/未知英文枚举（O03/C19/C22/G10）。
5. 标明过去预测与当前预测、简化回报与正式模型的关系（C07/C08）。

### 第二批：操作能完成、完成后看得见

真实追问；待办完成态与转交；人工情景判断入口；整组概率原子提交；设置发布后就地刷新；模型缺失导出保护；简报频道选择和内容阅读。维护通知合并，不再要求分析师逐批修翻译。

### 第三批：降低阅读与导航成本

设置拆分、首屏重排、公司页面按需加载、长报告独立阅读、统一视觉/时区/命名，旧版退出日常导航。管理员配置按问题和影响范围重排。

### 任务级验收（需以隔离测试项目执行写操作）

| 用户任务 | 完成标准 |
|---|---|
| 了解项目 | 非开发背景分析师30秒内指出当前观点、最大不确定性、最紧要待办，首屏不要求辨认系统术语。 |

| 处理待办 | 明白操作对象及影响，完成/排队/拒绝区分；卡片与计数一致；无需命令行或hash。 |
