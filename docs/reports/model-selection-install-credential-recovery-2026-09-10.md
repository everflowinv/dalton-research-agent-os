# Model-selection installation credential recovery

The first post-c84 Debate Map verification was refused with `credential_slot_unavailable` for the explicitly selected Gemini profile. The policy override survived reinstall, but the generated initial-screen configuration contained only credential references from the installer’s base brain tier. Preserving the choice text alone did not preserve a usable route.

Setup now resolves the effective chains of retained purpose overrides and carries their declared credential-slot references alongside the base tier. This includes explicit return-to-tier selections and governed retirement fallback. It reads references from registered profiles; no credential value is copied into reports or policies. Explicit caller-supplied extraction credential restrictions remain explicit.

Validation: 112 setup/model-selection tests passed. A regression creates a brain-tier installation with a separately selected Gemini verifier, reruns the real installer setup, and then routes and executes the verifier through the actual router under the regenerated credential set. Legacy no-policy credential scope remains unchanged. This patch is integrated for the next release, not deployed by the c84 runtime receipt.
