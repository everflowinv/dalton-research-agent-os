# Numeric capability feedback after an admitted upgrade

A saved numeric admission can already have taken up an earlier qualitative rejection while its answer remains unresolved. Advertising the earlier capability upgrade as a new executable operation causes the planner to combine its binding with the successor's period-replacement binding, which the normal validator correctly rejects.

`document-numeric-capability-supersession:0.1` removes only that earlier executable requirement after replaying the original and successor immutable admission bytes, identity hashes, saved plan/inquiry, exact rejection and frozen capability-upgrade proof. It also requires the same mission version, company, exact question, registered original/document hash, normalized targets and rebuilt source binding. Answer criteria may differ because the approved numeric upgrade adds explicit numeric requirements; both criteria hashes are retained. Candidate lookup is limited to 32 explicit successors; overflow, source mismatch, withdrawal or unverifiable input keeps the original requirement with an unverified diagnostic.

The feedback retains original observations, outcomes, fees and all successor failures. An admitted, partial or failed successor remains pending. A completed successor follows the existing successful formal-result path; this relationship does not establish completion, a Figure, a retry, or permission to spend. Its stable proof changes the existing feedback signature once, without an additional counter or paid task.
