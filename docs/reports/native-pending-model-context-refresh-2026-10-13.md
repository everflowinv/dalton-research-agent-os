# Native context refresh before model holds

The latest NTR context had 558 rows with fully resolved USD, USDPerShare and shares units. Its native normalizer hash was `6ab59008361e32fcc4139d214d7bfab988981d6d3502705869379519df2d2a8f`; the held-source membership contract requires `c7336e47f0328cf25c085cc2bb8a616e9b12cae7d4aae2e74bf1a0f7da37e97d`. The previous unit-only preflight therefore selected nothing. This is a context refresh omission, not evidence that the company lacks the original annual report.

Pending companies now receive native preparation before the specification lane consults holds about their previous input. Only native annual filings in the actual bounded model window are eligible for a normalizer refresh. The original owner reconstructs a complete context from held source bytes; the lane then repeats selection and rebuilds the state. The CLI uses the same preflight and refuses source failures before any model call. Current contexts are not refreshed on restart. Domestic unit behavior is unchanged.

A refused refresh is appended independently and never replaces the latest available context. Its versioned scope binds the exact filing hash and raw references, native evidence record including original document hashes and locators, current available context, expected normalizer, and existing raw objects' physical identity. An unchanged, hash-verified refusal suppresses another expensive parse. Source, context or rule changes enable a full new source proof. The physical fingerprint only suppresses work; it grants no numeric or paid authority. Failed refreshes remain explicit holds.

The `sec_native_filing_units` change is confined to model preflight. An exact whole-file SHA alias preserves its previous numeric normalizer identity; unknown modified source bytes cannot inherit the alias. No native parser, unit supplement, old context reader, paid task, Work identity, budget or repair allowance changes. Default backfill records omit the new optional refusal metadata.

Nine new tests cover two issuers, 20-F and 40-F, resolved units with stale contexts, immutable old rows and proof replay, restart idempotence, missing source then restored source, stable refusal caching, malformed cache/projection refusal, unknown source hash, and preparation before the existing paid permission check. It produced a prospective 560-row context while the production pointer stayed at the original 558-row version and SQLite total_changes remained zero. This is an offline proof of preparation, not a formally recorded context, specification or forecast. Natural deployment acceptance must observe the appended context, rebuilt model input and subsequent authorized result separately.
