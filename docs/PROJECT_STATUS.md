## 当前运行情况

当前运行包为 v0.11.2，源码 `58efab08`，于 2026-10-11 03:06 UTC 开始启动。五个环境已切换到同一安装包并读取共享设置。03:21 UTC，五个环境健康检查全部通过，21 个服务均使用新包，公网首页和总览页可访问。两个旧环境的首次页面刷新约用时十五分钟，已自然完成。固定公网入口继续用于全部环境。v0.11.1 已[正式发布](https://github.com/everflowinv/dalton-research-agent-os/releases/tag/v0.11.1)，v0.11.2 的公共发布等待完整 CI 通过。

01:53 UTC 的近九十分钟观察中，Hyperscaler 新增十一份正式研究计划，以及两份标为完成的微软数字结果；其中有复用的数字，不能按结果条数计算新增答案。另有三份结果仍缺证据。IT 服务没有新正式计划：必要的研究状态压缩后为 64,844 字节，超过程序内部 64,000 字节限制。两项目在该窗口均没有新增正式预测模型、研究档案或投资备忘录。

Amazon 已完成 RPO、加权平均剩余期限和未起租租约承诺三项数字研究，尚无正式财务模型。03:08 UTC 的新模型答案在保存阶段被拒：同一净利润事实在起草输入中属于利润表，保存校验却按原始现金流量表来源判断。离线回放已复现两处冲突，正在修复数据衔接。MSFT 也没有正式模型；GOOGL、META 保留旧预测，新模型各有未解决的校验或原文缺项。

管理员设置采用全机共用配置，现有、新建及恢复运行的项目均读取共享模型顺序和额度。行业框架、财务模型起草、文档事实抽取及事件判断的线上输出上限为 32,768，初筛为 64,000。部署时只调整了事件判断与初筛的输出上限，金额、模型顺序及其它设置保持原值。此前一次 Grok 事件判断返回 9,143 token，超过当时的 8,192 上限，系统暂停使用该配置一小时，随后按第二顺位调用 Opus；这段历史记录保留。

IT 服务当前两张材料额度卡分别对应 ACN、EPAM。用户此前的批准均已生效：每项上限为11 次检索、1.00 美元，累计记账11 次检索、0.105 美元。当前短缺的是下一步检索次数，金额仍有余额。检索本身也存在问题：复合中文问题与英文原文的关键词覆盖规则不匹配，明确提到 10-K／10-Q 的问题未正确选择申报来源。相关段落在库不代表整道研究问题已回答。

v0.11.2 已部署的修复包括：扩大规划任务的有限存储空间并重新检查旧输入长度拒绝；模型起草按保存后的有效预算建立新任务，并保留在途任务的原配置；改善净利润与 EPS 分子的建模和修正说明；按当前批准额度计算材料短缺，并将符合条件的已有原文交给后续阅读。新的模型和研究答案按公司逐项验收。

后续检查发现材料队列固定重复处理前几项、电话会数字任务的来源等级不匹配，以及已完成答案没有完整反馈给规划等问题。材料轮转、电话会数字研究和 EPS 分子状态补全修复已通过相关测试，尚未上线；其它修复单独推进。详见[研究任务执行跟踪](reports/research-followthrough-2026-10-11.md)。

部署后，CTSH 于 03:14 UTC、ACN 于 03:26 UTC 分别生成新的正式模型规格，尚未生成新的正式预测。ACN 投资判断已不再报函数错误，目前等待完整的三情景收益。EPAM 自动关联五份已有材料，仍缺利润率与一次性项目的核验结果。IBM、META 的申报单位证明请求此前没有轮到获取；DXC 的模型驱动尚未与精确数字上下文对齐。逐公司卡点与成果见[研究任务执行跟踪](reports/research-followthrough-2026-10-11.md)。

## 研究模块

| 模块 | 分析师可以做什么 | 系统保存什么 |
| --- | --- | --- |
| 研究项目 | 设定行业、公司范围、重点问题和预算；建立新项目 | 目标的每次修改、覆盖名单、来源和预算设置 |
| 资料与出处 | 阅读披露、纪要和研究资料；从结论打开原文 | 原始资料、获取记录、公司、期间与引用位置 |
| 公司与行业研究 | 查看业务分析、本所观点、反向观点和分歧 | 档案与行业框架的历次版本、采用的事实和待补问题 |
| 财务预测 | 检查历史与未来季度、业务驱动和现金流假设；导出底稿 | 申报口径、模型规格、假设、公式和计算结果 |
| 情景估值 | 比较悲观、基准和乐观情景；调整概率并说明依据 | 情景条件、概率、估值依据和修订记录 |
| 问答与决策 | 围绕行业或公司提问、继续追问；处理需要判断的事项 | 问答上下文、引用和分析师的决定 |
| 跟踪与复盘 | 查看事件、预测偏差及后续问题 | 事件判断、差异原因、后续任务和周报 |
| 运行管理 | 查看任务、模型、资料来源、费用和项目状态 | 调用费用、设置变更及项目创建、暂停、归档等记录 |

各项目分别保存研究记录，共用模型顺序、思考档位和上限由管理员统一维护。两个项目的投资备忘录均保留 Grok 4.7 第一，文档事实抽取保留 Muse Spark Contributor 第一。不能立即应用的项目显示待同步，恢复执行前先应用最新设置；页面可查看当前生效顺序和实际使用的服务。

周报正文与送达记录可在工作台查看。研究进展周报汇总项目进展、资料缺项和待处理事项；研究周报根据已有行业研究与出处生成。当前固定排期为纽约时间每周四 07:00。

## 已完成的验证

工作台的五个主要入口已逐页检查：研究总览、公司研究、智能投研问答、待办决策、投研规则与设置。检查覆盖主要按钮、出处查看、键盘操作和 320 像素窄屏。公司档案关闭后可返回原按钮，ACN 研究报告 HTML 已实际下载。问答与修改操作在隔离项目中测试；新项目创建、暂停、归档、恢复和删除也在隔离项目中走完了实际服务流程。

财务模型的隔离回放覆盖连续八个季度、季度与财年口径、年度 EPS、业务分部、债务利息、折旧摊销、现金流及情景估值。DXC 新申报的来源对应关系已修复，396 行财务上下文通过读取校验。SPY 十年价格历史已入库，共 2,514 个交易日。

研究规划现保留 IT 服务的全部五家公司和 Hyperscaler 的全部四家公司，以及未回答问题所需要的原文。数字任务绑定的旧版原文和最新版本可同时读取；文档抽取的已付费调用暂遇费用写入冲突时，系统保留结果并登记待补结算项。

财务表格中的“—”可通过悬停或“展开缺失说明”查看原因。常见缺项包括业务分部调整前后的对应关系、分部利润、税费明细、股数依据及公司自由现金流调整项。补充资料后，相关计算和研究问题继续更新。

接下来的验收重点是观察研究问题是否实际完成读取、核验并更新模型或结论，确认自动任务可以持续衔接。已发布版本与后续修复分别维护。设计决定见[架构决策记录](adr/)。
