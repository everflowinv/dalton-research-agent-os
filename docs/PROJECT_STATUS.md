## 当前运行情况

美国 IT 服务和 Hyperscaler 两个项目目前运行 v0.11.0（源码 `0dbec05f`）。截至本次核对，共有十六项经过核验并入库的不同数字答案：亚马逊三项、微软三项、EPAM 十项。EPAM 最近新增的八项是四个行业在 FY2025 和 FY2024 的收入金额，后续可以据此计算增长率。

两个项目的主要研究进程继续运行，22:31 UTC 的健康检查均通过。同一个数字换一段引用后重复入库的修复已通过相关测试，尚待部署。两个环境已通过管理员接口调高七个环节的单次输出上限：文档事实抽取 32,768；事件判断与零基复核各 8,192；研究规划、深层研究、财务模型起草各 16,384；投资备忘录 64,000 tokens。费用上限保持不变。当前批次保留启动时的设置，后续批次读取新配置；研究规划在下次服务重启后采用新上限。

两个项目的全部九家公司都保留在规划输入中。研究记录区分新计划、已执行任务和已经核验的答案；只取得部分证据的任务继续列出缺项。

## 研究模块

| 模块 | 分析师可以做什么 | 系统保存什么 |
| --- | --- | --- |
| 研究项目 | 设定行业、公司范围、重点问题和预算；建立新项目 | 目标的每次修改、覆盖名单、来源和预算设置 |
| 资料与出处 | 阅读披露、纪要和研究资料；从结论打开原文 | 原始资料、获取记录、公司、期间与引用位置 |
| 公司与行业研究 | 查看业务分析、本所观点、反向观点和分歧 | 档案与行业框架的历次版本、采用的事实和待补问题 |
| 财务预测 | 检查历史与未来季度、业务驱动和现金流假设；导出底稿 | 申报口径、模型规格、假设、公式和计算结果 |
| 情景估值 | 比较悲观、基准和乐观情景；调整概率并说明依据 | 情景条件、概率、估值依据和修订记录 |
| 问答与决策 | 围绕行业或公司提问、继续追问；处理需要判断的事项 | 问答上下文、引用和分析师的决定 |
| 跟踪与复盘 | 查看事件、预测偏差及后续问题 | 事件判断、差异原因、后续任务和周报 |
| 运行管理 | 查看任务、模型、资料来源、费用和项目状态 | 调用费用、设置变更及项目创建、暂停、归档等记录 |

各项目分别保存研究记录，管理员修改的共用模型设置同步到各活跃项目。两个项目的投资备忘录均按保存的 Grok 4.7、Opus 5.5 等候选顺序选择模型；保存、重新打开页面和实际模型选择已核对。模型顺序以管理员最新保存的设置为准。当前正在扩展全局设置的持久同步，使暂停或离线项目恢复时、新建项目启动时也采用最新设置，并将各环节上限纳入同一流程。

周报正文与送达记录可在工作台查看。研究进展周报汇总项目进展、资料缺项和待处理事项；研究周报根据已有行业研究与出处生成。当前固定排期为纽约时间每周四 07:00。

## 已完成的验证

工作台的五个主要入口已逐页检查：研究总览、公司研究、智能投研问答、待办决策、投研规则与设置。检查覆盖主要按钮、出处查看、键盘操作和 320 像素窄屏。公司档案关闭后可返回原按钮，ACN 研究报告 HTML 已实际下载。问答与修改操作在隔离项目中测试；新项目创建、暂停、归档、恢复和删除也在隔离项目中走完了实际服务流程。

财务模型的隔离回放覆盖连续八个季度、季度与财年口径、年度 EPS、业务分部、债务利息、折旧摊销、现金流及情景估值。DXC 新申报的来源对应关系已修复，396 行财务上下文通过读取校验。SPY 十年价格历史已入库，共 2,514 个交易日。

研究规划现保留 IT 服务的全部五家公司和 Hyperscaler 的全部四家公司，以及未回答问题所需要的原文。数字任务绑定的旧版原文和最新版本可同时读取；文档抽取的已付费调用暂遇费用写入冲突时，系统保留结果并登记待补结算项。

| 文章质量 | 真实验收样本通过数字与出处一致性检查和跨模型家族核验，但低、中思考强度两档均未通过研究质量评分。部分引用尚缺句级归属证明，低档样本存在事实重复。 |
| 费用核对 | 本轮新规划失败调用已结算；更早仍有发送状态或结算不完整的记录，继续按原记录核对。 |

财务表格中的“—”可通过悬停或“展开缺失说明”查看原因。常见缺项包括业务分部调整前后的对应关系、分部利润、税费明细、股数依据及公司自由现金流调整项。补充资料后，相关计算和研究问题继续更新。

接下来的验收重点是观察研究问题是否实际完成读取、核验并更新模型或结论，确认自动任务可以持续衔接，再完成发布整理。设计决定见[架构决策记录](adr/)。

## 版本与工程验证记录

v0.11.0 于 21:15 UTC 在两个项目启动，928 个打包源码文件及 62 项依赖通过安装校验。启动后的首次页面刷新仍较慢，期间研究执行和工作台接口持续工作。

前次修复已验证两个项目的完整估值只读计算分别用时 4.07 秒和 7.17 秒。Hyperscaler 一次规划因 Grok 回复超过单次输出长度而失败，费用已结算；后续状态更新后按候选顺序使用 Opus 完成了新计划。同一研究状态下的专门恢复仍待线上验证。

发布前的本地全量运行及后续相关模块复验分别留有记录。发布后的 GitHub 自动检查发现 Python 3.11 语法兼容、可选依赖和跨平台验收问题；修复已提交为 `acb6b809`。实际 Python 3.11 语法检查及相关测试通过，新的 Ubuntu 全量检查正在运行。线上服务仍使用上述 v0.11.0 安装版本。
