两个项目的主要研究进程继续运行。Hyperscaler 在 20:06 和 20:11 UTC 的周度检查中出现写入队列超时，20:16 UTC 的下一轮检查恢复成功，后续轮次仍在观察。下文列出的新修复尚待部署。

已部署的修复包括：按明确的问题标识避免重复派发、执行各环节设定的模型尝试次数、在原预算内恢复受旧格式错误影响的任务，以及在某一问题被拒绝后继续处理同一计划中的其他问题。后一项仍需观察真实任务验证；Hyperscaler 当前的旧计划尚在等待重试。

两个项目的研究审批项均为零。数字格式与接口问题由系统恢复或交给管理员检查。美国 IT 服务有一项 EPAM 资料查找请求达到累计额度上限；Hyperscaler 有三项原有资料查找请求达到各自累计次数上限，涉及微软未来催化剂和亚马逊季度业绩新闻稿。这些额度事项仍需决定是否追加。最新一项亚马逊任务在模型未返回内容后，被线上旧版误列为分析师待办，并重复生成汇总项；修复已通过当前记录回放，更新后模型问题归管理员处理，汇总卡片不再重复计为分析师决策。中文报告维护、预测偏差复核和周度运行反思分别显示处理进展。

待发布修复会把资料不适用的原因、缺少哪些原文证据，以及已经核验完成的指标范围一并交回研究规划。此前摘要只留下完成数量，容易让下一轮再次提出相近问题；新摘要保留指标定义、期间和出处，同时保留尚未解决的不同口径。EPAM 的下一轮计划已将原文未披露的同比改为已披露的收入金额，但旧版执行层仍按旧问题阻止派发；新代码允许经核验确实没有取得所需数字的任务，在原预算和同一版本原文内安排一次实质口径调整。两个项目的全部九家公司都保留在规划输入中。恢复执行、生成新计划和完成研究答案，在此分别记录。

## 研究模块

| 模块 | 分析师可以做什么 | 系统保存什么 |
| --- | --- | --- |
| 研究项目 | 设定行业、公司范围、重点问题和预算；建立新项目 | 目标的每次修改、覆盖名单、来源和预算设置 |
| 资料与出处 | 阅读披露、纪要和研究资料；从结论打开原文 | 原始资料、获取记录、公司、期间与引用位置 |
| 公司与行业研究 | 查看业务分析、本所观点、反向观点和分歧 | 档案与行业框架的历次版本、采用的事实和待补问题 |
| 财务预测 | 检查历史与未来季度、业务驱动和现金流假设；导出底稿 | 申报口径、模型规格、假设、公式和计算结果 |
| 情景估值 | 比较悲观、基准和乐观情景；调整概率并说明依据 | 情景条件、概率、估值依据和修订记录 |
| 问答与决策 | 围绕行业或公司提问、继续追问；处理需要判断的事项 | 问答上下文、引用和分析师的决定 |
| 跟踪与复盘 | 查看事件、预测偏差及后续问题 | 事件判断、差异原因、后续任务和周报 |
| 运行管理 | 查看任务、模型、资料来源、费用和项目状态 | 调用费用、设置变更及项目创建、暂停、归档等记录 |

各项目分别保存研究记录，管理员修改的共用模型设置同步到各活跃项目。两个项目的投资备忘录均按保存的 Grok 4.7、Opus 5.5 等候选顺序选择模型；保存、重新打开页面和实际模型选择已核对。只有“从文档抽取研究事实”环节改为 DeepSeek、Haiku、GLM 的顺序，其余阅读环节保留各自设置。

周报正文与送达记录可在工作台查看。研究进展周报汇总项目进展、资料缺项和待处理事项；研究周报根据已有行业研究与出处生成。当前固定排期为纽约时间每周四 07:00。

## 已完成的验证

工作台的五个主要入口已逐页检查：研究总览、公司研究、智能投研问答、待办决策、投研规则与设置。检查覆盖主要按钮、出处查看、键盘操作和 320 像素窄屏。公司档案关闭后可返回原按钮，ACN 研究报告 HTML 已实际下载。问答与修改操作在隔离项目中测试；新项目创建、暂停、归档、恢复和删除也在隔离项目中走完了实际服务流程。

财务模型的隔离回放覆盖连续八个季度、季度与财年口径、年度 EPS、业务分部、债务利息、折旧摊销、现金流及情景估值。DXC 新申报的来源对应关系已修复，396 行财务上下文通过读取校验。SPY 十年价格历史已入库，共 2,514 个交易日。

研究规划现保留 IT 服务的全部五家公司和 Hyperscaler 的全部四家公司，以及未回答问题所需要的原文。数字任务绑定的旧版原文和最新版本可同时读取；文档抽取的已付费调用暂遇费用写入冲突时，系统保留结果并登记待补结算项。

财务表格中的“—”可通过悬停或“展开缺失说明”查看原因。常见缺项包括业务分部调整前后的对应关系、分部利润、税费明细、股数依据及公司自由现金流调整项。补充资料后，相关计算和研究问题继续更新。

接下来的验收重点是观察研究问题是否实际完成读取、核验并更新模型或结论，确认自动任务可以持续衔接，再完成发布整理。设计决定见[架构决策记录](adr/)。

## 版本与工程验证记录

当前安装版本为 `927857c0`，18:49 UTC 在两个项目启动，926 个源码文件与安装版本一致。截至 19:06 UTC，两项目均通过完整健康检查。Hyperscaler 首次首页刷新约用 12 分钟，美国 IT 服务约用 17 分钟；期间研究执行和工作台接口持续工作，启动后的首次刷新仍较慢。

前次修复已验证两个项目的完整估值只读计算分别用时 4.07 秒和 7.17 秒。Hyperscaler 一次规划因 Grok 回复超过单次输出长度而失败，费用已结算；后续状态更新后按候选顺序使用 Opus 完成了新计划。同一研究状态下的专门恢复仍待线上验证。

问题标识去重通过 205 项相关测试，模型尝试次数上限通过 176 项，数字技术恢复通过 283 项，逐问题拒绝后继续执行通过 98 项。新增的一次数字口径调整通过 167 项相关测试与隔离研究回放。

发布候选完整运行了 13,623 项测试，出现 19 项断言失败、3 项错误，另有 6 项跳过。失败涉及更新后的页面文案、规划提示与测试样本，以及外接盘临时目录的识别。这些问题已逐一修复，502 项相关模块测试通过：规划与状态回放 183 项，执行、财务数据与发布演练 189 项，后台模型设置、文案与待办归类 130 项。原全量运行及各组复验分别留有记录。
